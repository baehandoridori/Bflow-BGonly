## 계획서와 실코드가 달랐던 지점

### ★ 1. 레일 이니셜이 접힌 상태에서 보이지 않음 (계획서 3-4 코드 결함 — 수정함)

계획서 3-4 의 레일 항목 이니셜 span:

```tsx
<span className={cn('hidden font-bold text-text-primary', collapsed && 'block')} …>
```

**문제:** 이 저장소의 `cn`(`src/utils/cn.ts`)은 `clsx` 단독이고 **tailwind-merge 가 아니다.** 따라서 접힘 상태의 className 은 `"hidden font-bold text-text-primary block"` 으로 **두 display 클래스가 함께 남는다.** Tailwind 가 생성하는 CSS 에서 `.hidden` 이 `.block` 보다 뒤에 오므로 `hidden` 이 이기고, 접힌 레일에서 이니셜이 렌더되지 않았다.

**실측(프리뷰):** 접힌 레일 텍스트가 `"0|0|3"` (개수만) — 목업의 `"주|3|친|2|…"` 와 불일치. 해당 span 의 `getComputedStyle().display === 'none'` 확인.

**수정:** 같은 파일의 형제 span 들이 이미 쓰고 있는 `!조건 && 'hidden'` 패턴으로 뒤집었다(새 의존성·리팩터 없음).

```tsx
<span className={cn('font-bold text-text-primary', !collapsed && 'hidden')} …>
```

수정 후 접힌 레일 텍스트 `"주|0|단|0|미|3"` — 목업과 일치. 확정 시안 A ⑤ "접혀도 이니셜·개수·드롭·점프 유지" 및 부록 A P-7 을 충족한다. 테스트 앵커에 걸리는 부분이 아니라 테스트 변경은 없다.

### 2. `SettingsSidebar.tsx` 의 사용자 노출 탭 라벨 `'권한·노출'` — **미수정(계획서 범위 밖), 한솔 판단 필요**

계획서 1-9 는 "`SettingsSidebar.tsx:26`·`AdminRoleSection.tsx:71` 의 '기능 노출' 문구를 '권한 관리'만 남게 정리(문구만)"라고 지정했다. 두 지점은 지시대로 정리했다.

그런데 실제로 **사용자에게 보이는** 설정 탭 라벨은 별도 위치인 `SettingsSidebar.tsx:83` 의 `label: '권한·노출'` 이다. 계획서가 `기능 노출`(공백 포함)로 검색해 작성된 탓에 `권한·노출` 은 목록에서 누락된 것으로 보인다. 지정 라인이 아니고 앵커도 없어(테스트 참조 0건), **절대 규칙("명시되지 않은 수정 금지")에 따라 건드리지 않았다.**

- 현재 상태: 이 탭에는 `AdminRoleSection`(권한 관리) + `CharacterFolderRootSection`(폴더 루트)만 남아, `노출` 은 삭제된 기능을 가리키는 잔여 문구다.
- 제안: `'권한 관리'` 또는 `'권한·폴더'` 로 변경. 승인 시 1줄 수정.

### 3. scroll-spy 임계 130px — 현재 헤더 높이에서 하이라이트가 한 섹션 뒤처짐 (계획서가 예고한 트레이드오프, 부록 C 후속)

계획서 작업 3 엣지 케이스가 "sticky 헤더가 130px 를 넘는 극단에서 하이라이트가 한 섹션 뒤처질 수 있음 — 동작 문제는 아니고 후속 조정 후보(부록 C)"로 이미 기록했고, "scroll-spy 임계 후속 기록"을 요구했다.

**실측:** 프리뷰의 sticky 헤더 실측값이 `--board-sticky-h = 174px`(헤더 162px + 12) 로, 상시 130px 을 넘는다. 레일에서 `미분류` 로 점프하면 미분류 섹션 상단이 스크롤러 기준 182px 에 정확히 놓이는데(= 174 + 8, `scroll-mt` 정상), 임계가 130px 이라 하이라이트는 바로 앞 섹션에 머문다. 즉 **뒤처짐은 극단이 아니라 기본 상태에서 발생**한다.

점프·드롭·순서 변경 등 기능 동작에는 영향이 없다. 계획서 지시(부록 C = 이번에 하지 말 것)에 따라 임계값은 그대로 두었다. 후속으로 `130` 을 `--board-sticky-h` 실측 기반으로 바꾸면 해소된다.

### 프리뷰 환경 제약 (코드 문제 아님)

인앱 Browser pane 은 화면에 표시되지 않으면 렌더링 스텝을 돌리지 않는다. 이 세션에서 **대조군 실험으로 `ResizeObserver` 콜백이 초기 observe 시점조차 발화하지 않음을 확인**했고(`fired === 0`), `requestAnimationFrame`·`scrollIntoView({behavior:'smooth'})`·CSS 트랜지션도 진행되지 않았다. 이 때문에:

- **P-9(ResizeObserver 로 `--board-sticky-h` 추적)** 은 프리뷰에서 검증 불가. 다만 헤더 높이가 실제로 162 → 128px 로 바뀌는 것과, 마운트 시 동기 `apply()` 로 `--board-sticky-h`(174px)가 설정되어 레일 `top:174px`·`max-height:522px`·섹션 `scroll-margin-top:182px` 로 정상 전파되는 것은 실측했다. RO 콜백 본문과 동일한 계산을 수동 적용해 값이 그대로 흐르는 것도 확인했다. **실기(Electron 창)에서 태그 접기 시 레일 top 이 즉시 따라가는지 최종 확인 필요.**
- P-3·P-7 의 트랜지션·P-8 의 rAF 는 각각 트랜지션 비활성화 / rAF setTimeout 폴리필로 최종 상태를 실측해 대체 검증했다.

이 제약은 이전 세션에서도 관측된 알려진 사항이다.

# B flow 리테이크 Slack 워크플로 설정

확인 기준: 2026-09-07, B flow 1.116.0 코드와 Slack 공식 안내.

**기존 댓글 알림 워크플로를 그대로 사용하면 됩니다.** 앱은 댓글과 같은 주소에 같은 이름의 변수 8개를 보내며, 리테이크 생성·새 담당 지정·수동 재알림 내용을 `comment`에 채웁니다. 새 웹훅이나 Slack 앱을 만들 필요는 없습니다. 아래는 설정 안내이며 실제 워크플로를 변경하거나 팀원에게 시험 메시지를 보내지는 않았습니다.

## 1. 기존 워크플로에서 확인할 것

Slack의 **도구 / 자동화 / Agents & tools → 워크플로 → 내가 관리하는 워크플로(Managed by you)**에서 기존 B flow 댓글 알림을 편집합니다. 메뉴 이름은 Slack 언어·화면 버전에 따라 다를 수 있습니다. 메시지 단계의 연필 아이콘을 누르고 본문·받는 사람·버튼을 확인하세요. [Slack 워크플로 편집 안내](https://slack.com/help/articles/17542172840595-Build-a-workflow--Create-a-workflow-in-Slack)

- 시작 조건은 기존 **웹훅에서 시작(From a webhook)**을 유지합니다.
- 아래 변수 이름 8개를 유지합니다. `EP`만 대문자입니다. 이름 변경이나 새 필수 변수 추가는 앱의 요청과 맞지 않게 됩니다.
- 이미 `name_target`에게 보내고 본문에 `comment`, 바로가기에 `deep_link`를 사용하는 워크플로라면 앱 쪽 연결을 다시 설정할 필요가 없습니다.
- 이 워크플로는 **댓글 멘션과 리테이크 알림이 함께 사용**합니다. 캐릭터 리깅 완성 공지 워크플로는 별개입니다.

| 변수 | 앱이 보내는 값 | Slack에서의 용도 |
|---|---|---|
| `comment` | 댓글 내용 또는 리테이크 제목·번호·내용·상태 안내·링크 | 텍스트, 본문에 전체 삽입 |
| `EP` | 에피소드 표시값 | 텍스트 |
| `part` | 파트 표시값 | 텍스트 |
| `scene` | 씬 표시값; 없는 경우 `전반` | 텍스트 |
| `time` | 한국 시간으로 표시한 발송 시각 | 텍스트 |
| `name_my` | 보낸 사람의 Slack ID; 리테이크에서는 미등록 시 이름 | 기존 타입 확인; 아래 설명 참조 |
| `name_target` | 알림을 받을 담당자 한 명의 Slack 멤버 ID | **사용자 ID(User ID)**, 받는 사람에 삽입 |
| `deep_link` | 해당 리테이크 또는 씬을 여는 `bflow://...` 주소 | 텍스트, 버튼의 링크 주소에 삽입 |

앱은 JSON 값 8개를 모두 문자열로 보냅니다. Slack 변수의 **사용자 ID** 타입도 JSON에서는 ID 문자열을 받습니다. Slack은 웹훅 변수로 텍스트·사용자 ID 등의 타입을 지원하며, 요청 값과 변수 이름이 일치해야 합니다. [Slack 웹훅 변수 안내](https://slack.com/help/articles/360041352714-Build-a-workflow--Create-a-workflow-that-starts-outside-of-Slack)

`name_my`가 현재 **사용자 ID** 타입이면 발신자에게도 Slack ID가 등록되어 있어야 합니다. 이름 문자열까지 허용하려면 **텍스트** 타입을 쓸 수 있지만, Slack ID가 이름/멘션으로 자동 표시되는 효과는 달라질 수 있습니다. 이미 댓글 멘션이 정상 표시되는 설정은 유지하고, 발신자·담당자의 Slack ID를 모두 등록하는 방법을 권장합니다. B flow 프로필에서 등록된 Slack 정보를 확인할 수 있으며 누락·수정은 관리자에게 요청하세요.

## 2. 복사할 공용 메시지 본문

다음 문구를 메시지 입력란에 붙여 넣습니다. **`{{comment}}` 같은 표시는 설명용 자리표시자입니다. 그대로 두면 실제 값이 연결되지 않습니다.** 각 자리표시자를 지운 뒤 같은 위치에서 **변수 삽입(Insert a variable)** 또는 **`{}` 아이콘**을 눌러 해당 웹훅 변수를 선택하세요. Slack 편집기에서 변수 항목으로 보여야 합니다. [Slack 변수 삽입 안내](https://slack.com/help/articles/17542172840595-Build-a-workflow--Create-a-workflow-in-Slack)

```text
🔔 B flow 알림

받는 사람: {{name_target}}
작업: {{EP}} / {{part}} / 씬 {{scene}}
보낸 사람: {{name_my}}
시간: {{time}}

{{comment}}
```

리테이크 알림의 `comment`에는 앱이 다음 내용을 자동으로 넣습니다. 아래 예시를 별도로 본문에 붙이면 중복되므로, 위 본문의 `comment` 변수 하나만 연결하세요.

```text
새 리테이크 배정 · re#3
창문 색상을 조금 더 밝게 수정해주세요.
작업을 시작하면 진행중, 수정을 마쳤으면 담당 완료를 눌러주세요.
리테이크 확인하기
```

수동 재알림에서는 첫 줄이 **리테이크 상태 확인 요청 · re#3**으로 바뀝니다. 링크가 변수 안에서 일반 텍스트로 표시되더라도 아래 버튼의 `deep_link` 연결은 별도로 설정할 수 있습니다.

## 3. 받는 사람과 버튼

**담당자 DM:** 메시지 전송 단계의 받는 사람 입력에서 변수 삽입을 눌러 **웹훅의 `name_target`**을 선택합니다. 본문에 이름을 넣는 것만으로는 받는 사람이 바뀌지 않습니다. 고정 채널 전송 단계를 그대로 두면 메시지는 그 채널에 게시됩니다. 앱은 담당자마다 요청을 하나씩 보내므로 `name_target` 한 항목으로 각 사람에게 전달할 수 있습니다.

**공용 버튼 권장값:**

| 설정 | 값 |
|---|---|
| 버튼 문구 | `B flow에서 확인하기` |
| 동작(Behavior) | **링크 열기(Open a link)** |
| 링크 주소 | 변수 삽입으로 **`deep_link`** 선택 |
| 한 번만 클릭(Single-click) | 끔 — 작업 중 같은 항목을 다시 열 수 있게 유지 |

메시지 단계에서 **버튼 추가(Add Button)**를 누르고 위 값을 설정한 뒤 **완료 → 저장 → 변경 사항 게시(Publish Changes)**를 선택합니다. 주소에 `deep_link`라는 글자나 특정 리테이크의 예시 주소를 직접 입력하지 말고, 반드시 변수를 연결하세요. [Slack 버튼 설정 안내](https://slack.com/help/articles/17542172840595-Build-a-workflow--Create-a-workflow-in-Slack), [여러 번 클릭 안내](https://slack.com/help/articles/26800170438419-FAQ--Slack-Workflow-Builder)

앱이 채우는 주소는 다음처럼 구분됩니다.

```text
리테이크 배정·재알림: bflow://retake/<리테이크 고유 ID>
기존 댓글 멘션:       bflow://scene/<시트 이름>/<씬 ID>
```

버튼은 항목을 열기만 합니다. Slack 버튼 클릭을 B flow의 **진행중**, **담당 완료**, **최종 완료**로 처리하지 않습니다. 상태는 B flow에서 직접 표시합니다.

**버튼 문구를 정확히 `리테이크 확인하기`로 쓰려면:** 위 공용 버튼의 문구만 바꿔도 되지만 **기존 댓글 알림에도 같은 문구가 표시**됩니다. 댓글 문구를 유지하려면 아래 선택 사항을 사용하세요.

## 4. 선택 사항: 리테이크에만 다른 버튼 이름

Slack에서 워크플로 분기를 사용할 수 있다면 같은 워크플로 안에서 메시지 단계만 나눌 수 있습니다. 이 기능은 Business+의 새 버전 및 Enterprise 플랜에서 제공되므로 현재 워크스페이스의 사용 가능 여부를 확인하세요. **필수 설정은 아니며, 분기 없이 공용 버튼 하나로도 두 종류의 링크를 전달합니다.** [Slack 분기 안내](https://slack.com/help/articles/42799802523283-Add-a-branch-to-a-workflow)

**단계 추가 → 유틸리티(Utilities) → 분기 추가(Add a branch)**에서 `deep_link`가 `bflow://retake/`를 포함하는 조건을 구성합니다. 조건 입력에서 텍스트 비교를 지원하는 경우의 권장 구성은 다음과 같습니다. 실제 표시되는 비교 연산자는 워크플로 설정에 따라 확인해야 합니다.

| 경로 | 메시지 제목 | 버튼 문구 | 버튼 주소 |
|---|---|---|---|
| `deep_link`에 `bflow://retake/` 포함 | `B flow 리테이크 알림` | `리테이크 확인하기` | `deep_link` 변수 |
| 그 외 기본 경로(Fallback) | `B flow 댓글 알림` | `댓글 확인하기` | `deep_link` 변수 |

양쪽 모두 받는 사람은 `name_target`, 본문 내용은 `comment`를 사용합니다. 기존 공용 메시지 단계와 분기 메시지 단계를 모두 실행하면 두 번 보내므로, 메시지 전송은 해당 분기에서 한 번만 실행되게 배치합니다. 저장 후 변경 사항을 게시합니다.

분기 기능이 없다면 공용 버튼을 유지하는 것이 가장 적은 변경입니다. 별도 워크플로를 복제하는 경우에는 새 주소가 생기므로 앱의 리테이크 전송 주소도 별도로 연결하는 개발 작업이 필요합니다. **복제만으로 앱이 새 워크플로를 찾아가지는 않습니다.**

## 5. 실제 사용 시 확인

- **Slack은 오는데 앱이 열리지 않음:** 최신 B flow를 설치한 Windows PC에서 확인하세요. 앱은 `bflow://retake/...` 수신을 지원하지만 Slack 편집기의 사용자 지정 주소 허용 및 설치된 PC의 연결 실행은 별도 확인 대상입니다. Slack 공식 버튼 안내에는 `bflow://` 지원 여부가 명시되어 있지 않아 이번 안내만으로 실제 클릭 성공을 보장하지 않습니다. URL 입력이 거부되거나 링크가 문자로 보이면 `deep_link`를 본문에도 변수로 넣어 주소를 보존하고, Windows의 실행 창에 그 주소를 붙여 앱 연결 자체를 구분해서 확인할 수 있습니다.
- **특정 담당자에게만 안 옴:** B flow의 해당 사용자 Slack ID와 워크플로의 받는 사람 `name_target` 연결을 확인합니다. 담당자가 여러 명이면 각자에게 별도 요청이 전송됩니다. 자기 자신, 이미 담당 완료한 사람, 담당 해제된 사람에게는 재알림을 보내지 않습니다.
- **일부 발송 실패:** 리테이크 저장과 Slack 전달은 별개입니다. 앱의 결과 안내를 확인하고 다시 알림을 보낼 수 있습니다. Slack 공식 문서상 웹훅 워크플로 요청 제한은 초당 1회입니다. [Slack 웹훅 제한 안내](https://slack.com/help/articles/360041352714-Build-a-workflow--Create-a-workflow-that-starts-outside-of-Slack) 앱은 같은 워크플로의 요청을 최소 1.1초 간격으로 보내며, 429 제한 응답은 Slack이 안내한 대기 시간을 적용해 최대 2회 재시도합니다. 여러 PC가 동시에 보내면 추가 제한이 생길 수 있고, 대기가 30초를 넘는 요청은 실패로 안내합니다. 전송 대기 중 로그인 사용자가 바뀌면 남은 요청은 취소합니다.
- **발송 요청 성공인데 메시지가 없음:** 앱의 성공은 웹훅 요청 수락 기준입니다. 워크플로의 게시 상태, 변수 타입, 메시지 단계 실행 결과까지 확인해야 실제 수신을 확인한 것입니다.
- **상태 버튼을 누르지 않은 담당자:** 등록자·검수 권한자가 B flow에서 수동 재알림을 보낼 수 있습니다. 담당자는 메인 화면의 내 리테이크 위젯에서도 진행 상태를 표시할 수 있습니다. 정기 자동 재알림은 이번 기능에 포함되지 않습니다.

실제 운영 확인은 담당자가 정해진 항목 한 건으로 **배정 알림 → 정확한 리테이크 열기 → 진행중/담당 완료 표시**, 그리고 기존 댓글 멘션 한 건으로 **댓글 내용·대상 씬 링크 유지**를 각각 확인하면 됩니다. 이 문서 작성 과정에서는 이 메시지들을 발송하지 않았습니다. 웹훅 주소는 비밀값이므로 안내·화면 공유에 넣지 않습니다.

## 코드 확인 위치

- `electron/retakeNotificationService.ts`: `buildRetakeWorkflowPayload`, 배정·재배정·재알림 대상 계산.
- `electron/main.ts`: 기존 댓글 웹훅과 리테이크가 같은 워크플로 주소를 사용.
- `electron/slackWorkflowTransport.ts`: 주소별 전송 간격, 429 재시도, 실제 전송 직전 로그인 확인.
- `src/services/slackWebhookService.ts`: 기존 댓글의 변수 8개와 씬 링크.
- `src/shared/bflowDeepLink.ts`: 리테이크 고유 ID 링크와 기존 씬 링크 해석.
- `src/components/settings/ProfileSection.tsx`: 등록된 Slack ID 표시 및 관리자 수정 안내.

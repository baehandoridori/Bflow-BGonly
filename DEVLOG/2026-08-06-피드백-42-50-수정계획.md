## 2. 아키텍처 전제

- **프로젝트**: B flow — Studio JBBJ 프로덕션 현황판. Electron + React 18 + TypeScript + Tailwind + Zustand + Supabase(PostgreSQL + Realtime). 저장소 `C:\Bflow-BGonly`.
- **데이터 경로 (필수 준수)**: 렌더러에서 Supabase 직접 호출 금지. 항상 `렌더러 서비스(src/services/supabaseService.ts) → preload(electron/preload.ts) → IPC(electron/main.ts) → electron/supabase.ts` 단일 경로.
- **낙관적 업데이트**: 모든 데이터 변경은 로컬 즉시 반영 → 저장 → 실패 시 필드 단위 조건부 롤백. 캐릭터 보드는 `pending*Fields` 버킷(`trackPendingFields`)으로 Realtime 수신과 낙관 반영의 경합을 필드 단위로 보호한다.
- **Realtime**: 메인 프로세스가 `characters / character_costumes / character_costume_images / episode_character_mapping / character_board_tabs` 를 구독해 `character-board:realtime` IPC 로 모든 창에 브로드캐스트 → 스토어 `receiveRealtime` 이 병합.
- **테스트**: Node 22 내장 `node --test`. `tests/*.test.ts` 는 package.json 의 `test:*` 스크립트에 **파일을 명시 나열해야 실행된다** (신규 테스트 파일은 반드시 등록). 직접 import 하는 유틸은 상대경로+`.ts` 확장자, `@/` alias 금지. 다수 테스트가 **소스 문자열 정규식 앵커** 방식이라 코드 수정 시 해당 앵커 갱신이 필수다.
- **검증 커맨드**: `npm run typecheck` / `npm run test:<스위트>` / `npm run build:vite`.
- **미리보기**: `npm run dev:renderer` → `http://localhost:5190/?preview=1` → mock 로그인 `배한솔` / `1234`. Electron 전용 기능(팝업 창, 클립보드 파일, 슬랙 전송)은 mock 이 null — 실기 확인 항목으로 분리한다.
- **슬랙 공지 구조**: 앱은 워크플로 트리거 URL 에 **평면 변수만 POST** (`title/CH_name/Path/bigo/image`) 하고, 메시지 서식(불릿·머리말·하이퍼링크)은 슬랙 워크플로 빌더 템플릿이 소유한다. URL 하드코딩은 의도된 패턴(변경 금지). `Path` 변수는 템플릿의 하이퍼링크 서식이 URL 로 쓰므로 `jbbj://open/` 링크 외의 텍스트를 섞으면 안 된다.
- **코드 규약**: 주석·토스트·커밋 메시지 한글. 기존 파일의 스타일(2스페이스, 싱글쿼트, 세미콜론)을 따른다.

## 엣지 케이스 & 주의사항
- **구버전 앱 공존:** dual-write(스칼라=배열 첫 값)로 구버전 화면에는 '첫 지정 복장'이 보인다. 구버전이 복장을 바꾸면 스칼라만 갱신돼 배열과 어긋날 수 있다 — 읽기 규칙(배열 우선, 비면 스칼라 폴백)상 새 버전 화면에는 배열이 이긴다. 완전 정합은 불가하며 자동 업데이트 롤아웃(수 시간~수 일) 동안의 수용 범위로 확정한다.
- **복장 삭제 시 잔존 id:** JSONB 배열엔 FK 가 없어 `ON DELETE SET NULL` 자동 정리가 없다. 소비처가 전부 `costumes.find/filter` 기반이라 죽은 id 는 표시에서 자연 무해화된다(탭 그룹 `characterIds` 와 동일 방어 패턴). DB 정리는 하지 않는다(범위 외 — 부록 C).
- **동시 편집:** 배열 하나에 대한 LWW 라 두 사용자가 동시에 서로 다른 복장을 추가하면 한쪽이 유실될 수 있다 — memo 와 동일 수준의 기존 충돌 창(~100ms Realtime 로 완화), 수용.
- **배지 색 변화 안내:** episodeRiggingStage 가 '가장 덜 진행'으로 바뀌므로 일부 에피소드의 리깅 배지가 이전보다 낮은 단계로 보일 수 있다 — update-notes 에 시나리오 톤으로 안내할 것("여러 복장을 지정하면 아직 안 끝난 복장 기준으로 표시돼요").
- `linkEpisode` 의 `upsertLink(..., {})` 빈 patch 호출은 (g-6) 기본값 변경으로 자동 호환된다.

# 작업 7 — 항목 47: 복장별 키 오버라이드 (대표 기준 키 유지)

## 문제/요청 요약
"대표되는 기준 키는 그대로 두고, 복장별로 따로 키 설정이 가능하면" — 키 커지는 신발 등 복장에 따라 키가 달라지는 케이스 대응. 현재 기준 키는 `characters.reference_height_px` 캐릭터 단위 단일 값이고, 입력란이 복장 패널에 있어 복장별 값처럼 보이지만 실제로는 캐릭터 전체가 공유한다.

## 근거

`DEVLOG/migrations/2026-07-08-character-board-duedate-height.sql:12` — `reference_height_px INTEGER` 는 characters 테이블 컬럼(CHECK 0<v<5000). `character_costumes` 에는 키 컬럼이 없다. `src/components/characters/CostumeDetail.tsx:160~177` (앵커: `commitHeight`) — 복장 패널의 기준 키 입력이 `setCharacterReferenceHeight(character.id, ...)` 로 캐릭터 레벨에 커밋. `src/components/characters/CharacterHeightEditor.tsx:89` (앵커: `onSave`) — '이미지로 조정' 드래그 에디터도 `setCharacterReferenceHeight(character.id, previewPx)` 로 캐릭터 레벨 저장. `src/components/characters/FeaturedImageSlot.tsx:411` (앵커: `autoHeightFromNatural(naturalSize.height)`) — 업로드 자동 설정은 대표 키가 null 일 때만 1회 기록(**변경하지 않는다** — '대표는 그대로' 원칙 그대로). `src/views/CharacterBoardView.tsx:259~277·558` — 키 비교 보기가 `c.referenceHeightPx` 만 소비.

쓰기 파이프라인(복장 필드 추가 시 흐르는 경로): DB 컬럼 → 타입(도메인+Row 2곳) → `rowToCostume` 매퍼 → 렌더러 `updateCharacterCostume` 화이트리스트 → 스토어 `updateCostumeField` Pick 목록 → UI. `electron/supabase.ts` 의 `updateCharacterCostume` 은 pass-through(4266행) 라 변경 불필요. 낙관 업데이트·롤백·Realtime pending 병합은 `applyCostumeUpdate` 가 범용 처리(1177행) — 필드 추가만으로 동작한다.

## 근본 원인
복장 단위 키 저장소가 없다. `character_costumes.height_px` nullable 컬럼을 추가하고, 유효값 규칙 `복장 오버라이드 ?? 대표 키` 를 한 헬퍼로 통일한다.

```ts
/**
 * 캐릭터 현황판 작업자/상태 필터 (피드백 48) — 씬 카드 필터(전체/미착수/진행중/완료)와 같은 의미를
 * 캐릭터 단위로 집계한다. 순수 함수 — node:test 직접 import 대상('@/' alias·비순수 import 금지).
 */
import { parseAssigneeNames } from './assigneeNames.ts';

export type CharacterStatusFilterValue = 'all' | 'not-started' | 'in-progress' | 'done';

type StageLike = {
  designStage: string;
  riggingStage: string;
  designAssignee: string | null;
  riggingAssignee: string | null;
  assignee: string | null;
};

/** 이 사람에게 배정된 트랙의 단계만 모은다. 레거시 assignee 필드는 양 트랙 겸용으로 본다. */
function tracksForAssignee(costumes: StageLike[], assigneeName: string): string[] {
  const stages: string[] = [];
  for (const c of costumes) {
    const legacy = parseAssigneeNames(c.assignee).includes(assigneeName);
    if (legacy || parseAssigneeNames(c.designAssignee).includes(assigneeName)) stages.push(c.designStage);
    if (legacy || parseAssigneeNames(c.riggingAssignee).includes(assigneeName)) stages.push(c.riggingStage);
  }
  return stages;
}

/**
 * 캐릭터 단위 작업 상태.
 * - 완료: 집계 대상 트랙이 1개 이상이고 전부 'done'
 * - 미착수: 집계 대상 트랙이 없거나(복장 0개 포함) 전부 'waiting'
 * - 진행중: 그 외 (하나라도 착수했고 아직 전부 완료는 아님 — 디자인만 끝난 캐릭터 포함)
 * assigneeName 이 있으면 그 사람에게 배정된 트랙만 집계한다.
 */
export function characterWorkStatus(costumes: StageLike[], assigneeName?: string | null): 'not-started' | 'in-progress' | 'done' {
  const stages = assigneeName
    ? tracksForAssignee(costumes, assigneeName)
    : costumes.flatMap((c) => [c.designStage, c.riggingStage]);
  if (stages.length === 0) return 'not-started';
  if (stages.every((s) => s === 'done')) return 'done';
  if (stages.every((s) => s === 'waiting')) return 'not-started';
  return 'in-progress';
}

/** 이 캐릭터에 assigneeName 이 배정돼 있는가 (작업자 필터의 1차 관문). */
export function characterHasAssignee(costumes: StageLike[], assigneeName: string): boolean {
  return tracksForAssignee(costumes, assigneeName).length > 0;
}

/** 필터 통과 여부 — 작업자 선택 시 배정 여부 먼저, 그 다음 상태 판정. */
export function matchesCharacterStatusFilter(
  costumes: StageLike[],
  filter: CharacterStatusFilterValue,
  assigneeName: string | null,
): boolean {
  if (assigneeName && !characterHasAssignee(costumes, assigneeName)) return false;
  if (filter === 'all') return true;
  return characterWorkStatus(costumes, assigneeName) === filter;
}

/** 작업자 드롭다운 옵션 — 전체 복장의 담당자(디자인·리깅·레거시) 유니온, 한국어 정렬. */
export function collectCharacterAssignees(costumes: StageLike[]): string[] {
  const set = new Set<string>();
  for (const c of costumes) {
    for (const n of parseAssigneeNames(c.designAssignee)) set.add(n);
    for (const n of parseAssigneeNames(c.riggingAssignee)) set.add(n);
    for (const n of parseAssigneeNames(c.assignee)) set.add(n);
  }
  return [...set].sort((a, b) => a.localeCompare(b, 'ko'));
}
```

# 작업 9 — 항목 49: 댓글 '복장+버전' 태그 (`bcostume`)

## 문제/요청 요약
캐릭터 댓글에 "도윤 봄옷 v2" 같은 복장+버전 태그를 남기고, 태그 클릭 시 좌측 카드가 그 복장으로 열리게 한다. 입력은 기존 `#` 자동완성에 복장 후보를 병합하는 방식.

## 근거

캐릭터 댓글은 씬 댓글과 같은 스택(`CommentPanelResizable → CommentPanel`, `comments` 테이블, `char:{characterId}` sentinel 키)을 쓴다 — `CharacterDetailModal.tsx:816` (앵커: `characterThread={{ characterId: selected.id`):
```tsx

          <CommentPanelResizable
            key={selected.id}
            sceneKey={`char:${selected.id}`}
            characterThread={{ characterId: selected.id, characterName: selected.name }}

기존 `#태그` 4단 파이프라인이 완결돼 있다: 입력(`useHashtagAutocomplete` → `HashtagDropdown` → `applyHashtag`가 `serializeHashTag` 삽입) → 저장(`comments.text` 문자열 안 직렬화 — **저장 경로 수정 불필요**) → 렌더(`tokenizeEntities` → `EntityText` 칩) → 클릭(`onHashClick ?? navigateToHashTarget`). `CommentPanelResizable` 은 이미 `onHashClick` 을 pass-through 한다(54행 주석 `4c PR2`).

### (d) `src/utils/hashtagCandidates.ts` — 후보 kind 확장 + 복장 후보 빌더

export function buildCostumeCandidates(
  costumes: { id: string; characterId: string; name: string; versionNo: number }[],
  characterName: string,
  filter: string,
): HashCandidate[] {
  const q = filter.trim().toLowerCase();
  return costumes
    .filter((c) => !q || c.name.toLowerCase().includes(q) || `v${c.versionNo}`.includes(q) || characterName.toLowerCase().includes(q))
    .map((c) => ({
      kind: 'costume',
      label: `${c.name} v${c.versionNo}`,
      context: characterName,
      tag: {
        kind: 'costume',
        label: `${characterName} ${c.name} v${c.versionNo}`,
        episodeNumber: 0, // costume kind 미사용 — serializeHashTag 가 참조하지 않는다.
        characterId: c.characterId,
        costumeId: c.id,
        versionNo: c.versionNo,
      },
    }));
}
```

## 엣지 케이스 & 주의사항
- **가드 재배치 누락 = 조용한 죽음.** 구현 후 반드시 (x-1) round-trip 테스트로 확인 — 콘솔 오류가 없어서 수동으로는 놓친다.
- **버전은 스냅샷 기록.** 복장 이름 변경·버전 증가와 어긋날 수 있다 — 클릭 시 안내 토스트가 그 갭을 설명한다. 과거 버전 화면 복원은 데이터가 없어 **불가능** — update-notes 에 "태그를 남긴 시점의 버전이 기록으로 남아요" 톤으로 안내.
- **삭제된 복장 태그** — '찾을 수 없어요' 토스트 + 캐릭터만 열림(핸들러 (h-2) 구현 그대로).
- **팝업 창** — 모달 로컬 state 변경이라 추가 작업 없이 동작. 팝업 안에서 씬 태그 클릭은 기존 동작 그대로.
- **`extractMentions`/`MENTION_REGEX` 동기화 경고(entityTokens.ts 8~9행 주석)** — 이번 변경은 hash 정규식만 건드린다. 멘션 쪽을 건드리지 말 것.
- 씬 댓글창에는 복장 자동완성을 넣지 않는다(캐릭터 문맥이 없어 후보를 좁힐 수 없음) — 클릭·붙여넣기만 지원(범위 외 아님, 의도된 설계).

## 4. 계획서와 달라진 지점

### 4-1. before 블록·라인 번호 — 불일치 0

계획서의 모든 before 블록이 실파일과 **정확히 1회씩** 일치했고, 병기된 라인 번호도 어긋나지 않았다(`AddCharacterModal.tsx` 79행, `CharacterBoardView.tsx` 230·779행, `CharacterDetailModal.tsx` 326·361·626·931행, `CostumeDetail.tsx` 28·134·297행, `characterFolderService.ts` 49행, `WidgetPopup.tsx` 48·1126행, `characterFeedbackBatch.test.ts` 27행). 앵커 검색으로 위치를 재확정해야 했던 경우도 없었다. 중단·건너뛴 작업 없음.

작업 트리가 CRLF 이므로 스크립트 치환 시 `\r\n` 을 LF 로 정규화해 매칭하고 다시 CRLF 로 되돌리는 방식을 썼으며, 매 치환마다 "before 가 정확히 1회 매치"를 강제했다.

### 4-2. `test:calendar` 가 이 워크트리에서 2건 실패 (계획서 기준선은 1건)

계획서는 기존 실패 1건(`ScheduleView counts every event overlapping the displayed month`)을 예고했다. 실제로는 2건이 실패한다.

1. `ScheduleView counts every event overlapping the displayed month` — 계획서가 예고한 **기존 실패**. 범위 밖이라 건드리지 않았다.
2. `ElectronAPI calendar event write inputs expose only fields accepted by IPC` — **환경 아티팩트**. `tests/calendarIpcValidation.test.ts:1487` 이 `join(process.cwd(), 'node_modules', 'typescript', 'bin', 'tsc')` 를 하드코딩하는데, 이번 작업은 git worktree(`.claude/worktrees/…`)에서 진행했고 워크트리에는 자체 `node_modules` 가 없다(전부 부모 저장소 `C:\Bflow-BGonly\node_modules` 에서 해석된다). 실패 원인이 `MODULE_NOT_FOUND: …\node_modules\typescript\bin\tsc` 인 것을 확인했다. 이번 diff 는 캘린더·`src/types`·tsconfig 파일을 하나도 건드리지 않았다(`git diff --name-only origin/main` 로 확인). 본 저장소 정상 체크아웃에서는 재현되지 않을 것으로 본다.

계획서 부록 B의 지시대로 `npx vite build && node scripts/generate-manifest.js --allow-missing-installer` 를 직접 실행해 빌드 통과를 증명했다.

### 4-3. 독립 검증에서 잡아 되돌린 불일치 1건 (테스트 픽스처 백슬래시)

구현 후 계획서 대조 검증(6개 차원 병렬 + 적대적 재검증)을 돌렸고, 5개 차원은 지적 없음, 1건이 확정됐다.

`tests/characterName.test.ts:93` 의 `const root` 가 계획서 (f-2) after 코드의 `'G:\\공유 드라이브\\...'`(이스케이프된 백슬래시)가 아니라 `'G:\공유 드라이브\...'`(단일 백슬래시)로 들어갔다. JS 문자열에서 `\공`·`\사`·`\[` 는 인식되지 않는 이스케이프라 백슬래시가 소거돼, 실제 런타임 값이 구분자 없는 `G:공유 드라이브사우스 코리안 파크[]사코팍 캐릭터 세팅` 이 된다. `assert.ok(msg.includes(root))` 가 같은 변수를 재사용하는 왕복 단언이라 테스트는 그대로 통과했고(159/0) 어떤 게이트에도 걸리지 않았지만, "윈도우 경로 원문이 확인 문구에 그대로 실린다"는 이 테스트의 의도가 무력화된다.

원인은 셸 heredoc 이 `\\` 를 `\` 로 접은 것이다(다른 추가 라인의 정규식 이스케이프는 원래 단일 백슬래시라 영향이 없었다). 계획서 표기와 바이트 단위로 같아지도록 되돌렸고, 이 줄은 성격상 작업 1의 것이므로 새 커밋을 만들지 않고 **작업 1 커밋을 amend 한 뒤 나머지 3개를 cherry-pick 해 이력을 다시 썼다**(계획서가 지정한 5커밋 구성 유지, `--force-with-lease` 로 push). 재작성 전후 트리 차이는 이 한 줄뿐이며(`git diff` 로 확인), 네 커밋 경계에서 `test:character` 155 → 157 → 159 → 159 · fail 0 과 `typecheck` 통과를 다시 실측했다.

### 4-4. 그 밖에 계획서와 달라진 코드·문구 — 없음

위 1건을 제외하면 after 코드 블록은 전부 계획서 표기 그대로 적용했다. 계획서에 없는 리팩터·포맷 변경·기능 추가는 하지 않았다.

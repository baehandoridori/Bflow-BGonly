### 4-4. 코덱스 리뷰 반영 (계획서 밖)

코덱스 지적은 스킬 규칙대로 P1·P2 를 모두 반영했다. 계획서의 결정과 달라진 것은 아래와 같다.

- **미리보기 저장(계획서 §6-7 "mock 은 in-memory, 새로고침하면 사라짐" 을 뒤집음)**: AGENTS.md 의 테스트 모드 동등성 규칙에 따라 `src/mocks/threadTodoPreviewStore.ts` 로 옮겼다 — localStorage 저장, Web Locks 로 쓰기 직렬화, BroadcastChannel 로 다른 창에 한 번 알림(자기 방송 무시), 서버 래퍼와 같은 규칙·문구, 저장소 읽기·쓰기가 실패하면 그 창 메모리로 전환.
- **사이드바 새 창 버튼(계획서 §6-8 의 `delay-300` 투명 구간을 없앰)**: opacity 대신 visibility 로 숨겨 보이는 순간부터만 눌리고, 키보드는 `group-focus-within` 으로 드러난다. 펼침 전환 중 아이콘 위에 겹치지 않게 사이드바 폭 전환(350ms)이 끝난 뒤에만 그린다.
- **팀 할 일 휴지통**: 같은 방식으로 visibility 로 숨겨, 투명한 채 확인 없이 지워지는 구간을 없앴다.
- **실시간 재연결**: 재연결에 성공한 첫 join 에서 `onThreadTodosChange` 를 한 번 호출해 열린 섹션이 다시 읽는다(§5-1 #2 를 수정으로 전환).
- **미리보기 새 창**: `widgetOpenPopup` mock 이 Electron 과 같은 `#widget-popup/{widgetId}` 해시로 같은 앱을 브라우저 새 창에 연다(막히면 `ok:false`).
- **스크롤 보정의 '막 연 패널' 조건**: 섹션 마운트 뒤 1초 안에 첫 목록이 온 경우에만 맨 아래로 다시 스크롤하고, 그 뒤엔 바닥 거리만 본다(늦게 온 목록이 위로 올려 읽던 사람을 끌어내리지 않게).
- **추가 실패 문구**: 입력창이 비었으면 바로 되돌리고, 새로 치는 중이면 줄 세웠다가 입력창이 비는 순간 하나씩 다시 채운다(연달아 실패하거나 새 문구를 지워도 잃지 않음).
- **문서**: AGENTS.md 에 '팀 할 일 경계 (v1.118.0)' 절, CLAUDE.md 에 필수 규칙 10, ROADMAP.md 진행 현황(7차).
- **미리보기 저장소 보강(8차)**: 성공한 읽기 결과도 메모리에 남겨, 나중에 저장소 접근이 막혀도 마지막으로 본 목록을 유지한다.
- **길이 기준(9차, 계획서의 UTF-16 `length` 검사를 바꿈)**: 서버 PostgreSQL `length()` 처럼 문자(코드 포인트) 단위로 센다(`threadTodoCharCount`). 입력창 `maxLength` 는 200×2 로 두어 이모지 200자를 막지 않고, 정제 뒤 200자를 넘으면 "할 일은 200자까지 적을 수 있어요" 안내와 함께 추가 버튼을 잠근다.
- **실패 문구·스크롤 보정 다듬기(10차)**: 두 추가가 같은 렌더 전에 실패해도 첫 실패가 입력창을 곧바로 예약한다. '막 연 패널' 보정은 즉시 끌어내리지 않고 60ms 뒤 목록이 아래로 움직이는 중이거나 옛 바닥 근처일 때만 새 바닥까지 이어 준다(`shouldFollowCommentListToBottom`) — 그사이 위로 올려 읽던 사람은 건드리지 않는다.

### 6-4. 이 PR 이전부터 있던 보안 문제 — 별도 작업으로 분리

`users` 테이블은 초기 스키마의 `allow_all` 정책과 2026-09-06 마이그레이션의 `GRANT UPDATE (name, role, …) TO anon` 때문에, 앱에 들어 있는 공개 키만으로 역할을 `admin` 으로 바꾸거나 같은 이름의 계정 행을 넣을 수 있다(레포 마이그레이션 파일 기준, 라이브 권한은 미확인). 세션 토큰 래퍼(간트·팀 할 일)의 관리자·이름 판정이 모두 이 행을 믿는다. 이번 브랜치가 만든 노출은 없고(팀 할 일 테이블 자체는 anon 직접 권한 0), 댓글·씬 등 기존 테이블이 이미 더 넓게 열려 있다. 라이브 권한 확인과 `users` 쓰기를 세션 토큰 래퍼로 옮기는 계획은 별도 작업으로 제안해 두었다.

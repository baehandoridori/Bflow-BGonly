## 계획서와 실제 코드가 달랐던 지점

**작업 1~6 은 없음.** before 블록 22건이 전부 실파일과 글자 단위로 일치했고, 앵커 재검색이 필요한 경우도 없었다.

**작업 7 에 계획서 누락 1건 — `package-lock.json` 버전 동반 갱신.**
계획서 작업 7 은 `package.json` 만 지시하지만, `tests/playgroundMarketUiWiring.test.ts:13-14` 가
`packageLock.version` 과 `packageLock.packages[''].version` 이 `packageJson.version` 과 같기를 단언한다.
`package.json` 만 올리면 `test:playground` 가 461 → 460 pass / **1 fail** 이 된다(실제로 재현 후 발견).
직전 릴리스 커밋(`0978dcf` v1.91.1)도 `package-lock.json` 을 함께 올렸음을 확인하고 같은 방식으로 2줄만 수정했다.
→ **다음 회차 계획서 작성 시 "버전 = package.json + package-lock.json 2곳" 으로 명시할 것.**
라인 번호만 작업 1 의 제거(-9줄) 이후 `CharacterBoardView.tsx` 에서 아래로 밀렸는데(계획서 364행 → 실제 355행),
계획서가 병기한 앵커(`h-full overflow-y-auto p-6`)로 즉시 재확정되어 문제되지 않았다.

계획서가 "파일에서 확인 후 결정"으로 남겨둔 두 지점의 확인 결과:

- `CharacterImageFrame` 의 `fit` 은 **optional**(`DEFAULT_CHARACTER_IMAGE_FIT` 폴백 존재) — 계획서 의도대로 `CharacterListRow` 의 1:1 썸네일에서 생략 유지. `fit={undefined}` 우회 불필요.
- `useCharacterBoardAccessState()` 반환은 `{ allowed, loading, error, retry }` — 계획서 6-2 게이트 래퍼 코드가 그대로 컴파일됨.

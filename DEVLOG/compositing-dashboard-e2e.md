# 컴포지팅 대시보드 — E2E 시나리오 체크리스트

> v1.30.0 (2026-05-23)
>
> 한솔님이 정식 빌드 전 / 배포 후 / 다음 릴리스 회귀 테스트 시 사용.
>
> Spec: `docs/superpowers/specs/2026-05-21-compositing-dashboard-design.md` (특히 § 3 핵심 사용자 흐름)

---

## 사전 준비

- [ ] **두 대의 PC** (또는 두 창) 준비 — Realtime 동기화 확인용
- [ ] 한 대는 **컴포지터 계정** (`isCompositor = true` or 어드민/배한솔), 다른 한 대는 **비컴포지터** (또는 일반 팀원)
- [ ] 데이터: 활성 에피소드가 최소 2개 이상, 각각 파트 A/B/C/D 의 씬 5개+ 가 있어야 함
- [ ] 두 사용자 모두 같은 에피소드(예: EP05)를 열어 두기

---

## 시나리오 A — 컴포지터가 단계를 바꾼다

1. [ ] 컴포지터 계정으로 로그인 → 사이드바 **"컴포지팅"** 클릭
2. [ ] 마지막 본 EP 가 자동 로딩되는지 확인 (`preferences.lastCompositingEpisode`)
3. [ ] 씬 카드들이 순차적으로(cascade) 살짝 들어오는 모션 — 너무 길지 않게 (~1초 안에 다 완료)
4. [ ] 한 씬 카드 위에 마우스를 올림 → 옆 카드들이 살짝 들썩이는지 (dock-lift)
5. [ ] 그 카드를 한 번 클릭 → 위로 떠오르고 glow 가 차분히 보이는지 (saturated 하지 않게)
6. [ ] 같은 카드를 한 번 더 클릭 → 상세 모달 열림 (기존 씬 상세 모달 + 위에 컴포지팅 단계 칩)
7. [ ] 모달 위 단계 칩에서 **"취합 완료"** 클릭 → 카드 단계 색이 보라색으로 즉시 바뀌는지
8. [ ] 모달의 키보드 `1`~`6` 으로도 단계 변경 시도 → 1=배치, 2=취합중, 3=취합완료, 4=보정중, 5=오류, 6=완료
9. [ ] 단, 메모 입력 칸에 포커스 있을 때 `1` 을 누르면 단계 안 바뀌고 글자로 입력되어야 함
10. [ ] 모달 닫고 → 카드 상태가 유지되는지

## 시나리오 B — 비컴포지터는 변경 못 한다 (read-only)

1. [ ] 비컴포지터 계정으로 로그인 → 사이드바 "컴포지팅" 클릭
2. [ ] 헤더 우측에 "지금 같이 보는 사람" 아바타 칩이 떠 있는지 (시나리오 A 의 컴포지터가 동시 접속이면)
3. [ ] 안내 띠가 떠 있는지 (첫 진입 한 번만, 닫으면 다시 안 뜸)
4. [ ] 헤더의 상태 필터에서 **"오류"** 칩 클릭 → 다른 단계 카드 dim, 오류 카드만 강조
5. [ ] 한 카드 클릭 → 상세 모달 열림
6. [ ] 모달의 단계 칩이 **disabled** (회색, 클릭 안 됨)
7. [ ] "컴포지터만 단계를 변경할 수 있습니다" 같은 안내 텍스트가 보이는지
8. [ ] 키보드 1~6 눌러도 단계 안 바뀌어야 함

---

## 시나리오 C — EP 전환

1. [ ] 컴포지터 계정으로 로그인, EP05 보고 있음
2. [ ] 헤더의 EP 칩 (EP1·EP2·…) 에서 **EP6** 클릭
3. [ ] 화면이 부드럽게 전환 (잠깐 fade-out → EP6 데이터 로드 → cascade)
4. [ ] EP6 의 파트/씬이 정상적으로 표시되는지
5. [ ] 핀해 둔 카드, 일괄 선택된 카드가 EP 전환 시 **모두 해제**되는지 (이전 EP 의 stale 상태 안 남아야 함)
6. [ ] 상세 모달이 열려 있었으면 EP 전환과 함께 닫혀야 함
7. [ ] 앱 재시작 → 사이드바 "컴포지팅" 다시 클릭 → EP6 가 자동 진입 (마지막 본 EP 저장 확인)

## 시나리오 D — Realtime 동기화 (두 PC)

1. [ ] PC1 (컴포지터): EP05 a008 카드 → 상세 모달 → "보정 중" 클릭
2. [ ] PC2 (다른 사용자, 같은 EP05 보고 있음): 0.1~1초 안에 a008 카드 점이 노란색으로 부드럽게 전환
3. [ ] PC2 의 a008 카드가 잠깐 색 펄스 + 우상단에 PC1 사용자 프로필 아이콘이 2~3초 떠 있다 사라지는지
4. [ ] PC1 도 인터넷이 잠깐 끊겼다가 다시 연결되면 PC2 의 변경분이 자동으로 받아지는지
5. [ ] 같은 씬을 두 명이 거의 동시에 다른 단계로 바꾸면 — 마지막 변경이 우선 (Last-Write-Wins)
6. [ ] Supabase 에 저장 실패 시 — 잠깐 변경이 보였다가 자동으로 이전 상태로 복귀 (롤백)

---

## 시나리오 E — 오류 사유 입력

1. [ ] 컴포지터 계정, EP05 a015 카드 → 상세 모달
2. [ ] 단계 칩에서 **"오류"** 클릭
3. [ ] 오류 사유 5종 칩 펼침 (파일 미싱 / 옥에티 수정 / 리테이크 / 취소된 씬 / 기타)
4. [ ] "기타" 클릭 → 자유 입력 텍스트 칸 노출
5. [ ] "프리미어에서 누락된 클립" 입력 → 자동 저장 (또는 명시적 저장 버튼 없이 blur 시 저장)
6. [ ] 모달 닫기 → a015 카드 점은 주황, 카드 위에 "기타 — 프리미어에서 누락된 클립" 라벨 truncate 표시
7. [ ] 다른 사용자 PC 에서도 a015 카드에 같은 오류 사유가 표시되는지 (Realtime)

## 보너스 시나리오 — UX 디테일

### F. 일괄 선택 + 일괄 단계 변경

1. [ ] 컴포지터, EP05
2. [ ] Ctrl(Mac은 Cmd) 누른 채 a001, a003, a005 클릭 → 세 카드가 일괄 선택 (좌상단 체크 마크)
3. [ ] 화면 하단에 작은 바 (`{N}개 선택`) 뜨는지
4. [ ] 빈 공간 드래그로 a008~a012 범위를 선택 → 다 일괄 선택에 추가되는지
5. [ ] 같은 파트 안에서 a002 클릭 → Shift+a006 클릭 → 사이 범위 전체 선택되는지
6. [ ] 하단 바의 "취합 완료" 칩 클릭 → 선택된 모든 씬이 한꺼번에 단계 변경
7. [ ] 선택 해제: 하단 바의 X 클릭 또는 Esc 키
8. [ ] EP 전환 시 일괄 선택도 같이 해제

### G. 다크/라이트 모드 토글

1. [ ] 설정 → 표시 → 모드를 "라이트" 로 토글
2. [ ] 컴포지팅 화면 전체가 즉시 라이트 톤으로 전환 (화면 깨짐 X)
3. [ ] Status 6색이 흰 카드 위에서 잘 보이는지:
  - 배치 (회색) — 너무 가라앉지 않게
  - 취합중 (파랑) — 잘 보임
  - 취합완료 (보라) — 잘 보임
  - 보정중 (노랑) — 너무 흐릿하지 않게
  - 오류 (빨강) — 너무 강하지 않게 (saturated X)
  - 완료 (청록) — 잘 보임
4. [ ] 핀한 카드의 glow 가 흰 카드 위에서도 인식 가능한지
5. [ ] 안내 띠가 흰 배경에서 너무 묻히지 않는지
6. [ ] 다크 모드 다시 토글 → 모든 색 정상 복귀

### H. prefers-reduced-motion (접근성)

1. [ ] OS 설정에서 "동작 줄이기 / Reduce motion" 활성화 (Windows: 설정 → 접근성 → 시각 효과 → "애니메이션 효과 보기" 끄기)
2. [ ] 앱 재시작 → 컴포지팅 화면 진입
3. [ ] cascade 모션이 거의 없거나 200ms fade-in 으로 단순화되는지
4. [ ] 카드 호버 dock-lift 가 즉시 적용 (transform 흔들림 X)
5. [ ] 핀한 카드의 glow pulse 가 단순 box-shadow 로 대체

### I. 안내 띠 영구 dismiss

1. [ ] 첫 진입 시 헤더 아래 안내 띠가 뜸
2. [ ] 우측 X 버튼 클릭 → 닫힘
3. [ ] 페이지 새로고침 → 안내 띠 안 떠야 함 (localStorage 플래그)
4. [ ] 다른 EP 로 전환 후 다시 돌아와도 안 떠야 함
5. [ ] (선택) 헤더의 ? 버튼이 있으면 다시 띄울 수 있어야 함 (후속 polish)

### J. 권한 변경 즉시 반영

1. [ ] 비컴포지터로 로그인 → 단계 변경 disabled 확인
2. [ ] DB 에서 그 사용자의 `is_compositor` 를 `true` 로 변경
3. [ ] 앱에서 단계 변경 시도 — 권한 변경이 다음 로그인 후 반영되는지 확인 (앱 재시작 필요할 수도)
4. [ ] 한솔(배한솔) 계정과 어드민 계정은 `isCompositor` 와 무관하게 항상 변경 가능

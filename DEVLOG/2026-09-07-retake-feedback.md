# 캐릭터 댓글·리테이크 진행 확인 개선

기준: `origin/main` aa4ac56e, 구현 버전 1.116.0. 이번 요청의 네 항목을 기존 화면·담당 권한·Supabase/IPC 흐름에 연결한다.

## 동작

1. 캐릭터 카드/간단 카드/리스트/사용자 탭 이름 옆에 기존 compact 댓글 배지 표시. 댓글 0개는 숨기고 캐릭터 전체 댓글 수와 읽음 상태를 사용한다.
2. 기존 리테이크 화면에서 담당자가 있을 때 빠졌던 공용 담당 진행·완료멘트·최종 완료 바를 연결한다. 담당 전원 완료와 요청자/컴포지터 권한을 유지한다.
3. 기존 리테이크 화면과 세트 허브 모두 씬 상세를 로컬 모달로 연다. 배경 목록·필터와 상세의 리테이크 초점을 유지한다.
4. 신규 리테이크 저장 후 담당자에게 기존 Slack workflow를 호출한다. 기존 항목의 담당 지정·변경에서는 새로 추가된 담당자에게만 앱·Slack 알림을 보낸다. 재알림은 요청자/검수 권한자가 미완료 담당자에게 수동 발송하며 30초 중복 방지와 발송 결과를 제공한다. 메인 위젯에서 본인 진행중/담당 완료를 직접 표시할 수 있다. 위젯 없는 개인 배치에는 작은 진행 상태 안내가 나온다.

## 알림과 바로가기 경계

- Slack 전송 실패는 이미 성공한 리테이크 저장을 실패로 바꾸지 않는다. 일부 실패/Slack 계정 미등록을 별도로 표시한다.
- 재알림 대상·권한은 main 프로세스가 최신 DB 리테이크와 현재 로그인 사용자로 다시 확인한다. 완료한 담당자와 보낸 본인은 제외한다.
- `bflow://retake/<revisionId>`는 리테이크 고유 ID로 찾는다. 로그인/연결 대기 중 요청을 보존하고 세트 소속은 해당 세트·행, 그 외 항목은 기존 리테이크 상세로 연다.
- 생성 알림은 기존 실시간 수신과 로그인 시 미완료 배정 조회로 보강한다. 수동 재알림의 앱 내 전송은 실시간 방송이며, 앱이 꺼진 동안 보낸 개별 재알림 이력은 DB에 따로 저장하지 않는다. 오프라인 담당자에게는 Slack이 전달 경로이며 다음 로그인에는 미완료 배정 자체를 확인한다.
- 담당 변경 알림도 최신 저장값과 이전 담당자를 비교한다. 기존 담당자에게 같은 알림을 다시 보내지 않으며, 담당 해제만 하거나 저장이 실패하면 발송하지 않는다. 재배정 이벤트는 별도 ID를 사용해 동일 항목을 다시 맡아도 새 알림으로 표시한다.
- Slack workflow는 URL별 공용 큐에서 최소 1.1초 간격으로 보낸다. 429만 `Retry-After`에 따라 최대 2회 재시도하고, 대기·재시도 후 실제 전송 직전에 세션을 다시 확인한다. 응답이 불확실한 네트워크 오류는 중복 발송을 막기 위해 자동 재시도하지 않는다.
- 하루 한 번 자동 재알림은 추가하지 않는다. 수정이 실제 끝났는지를 파일 변경만으로 판단해 완료 처리하지 않는다.

## Slack 워크플로 연결

기존 webhook 변수 8개 `comment`, `EP`, `time`, `scene`, `name_my`, `name_target`, `part`, `deep_link`를 그대로 사용한다. URL·비밀값은 이 문서에 기록하지 않는다.

- `name_target`: 담당자의 Slack ID, `name_my`: 발신자 Slack ID(미등록 시 이름).
- `comment`: 리테이크 내용, 진행 상태 확인 안내와 리테이크 링크.
- `deep_link`: `bflow://retake/<revisionId>`.
- **실제 메시지의 버튼 문구는 Slack Workflow Builder가 소유한다.** 메시지 단계에서 URL을 `deep_link` 변수에 연결하고 `리테이크 확인하기` 문구를 설정해야 한다. 기존 댓글 워크플로와 템플릿을 공유하므로 문구 변경 시 댓글 알림에도 영향을 주는지 확인한다. 리테이크 전용 문구가 필요하면 기존 워크플로를 복제해 전용 URL로 분리하는 후속 설정이 필요하다.
- [Slack 공식 webhook 변수 안내](https://slack.com/help/articles/360041352714-Build-a-workflow--Create-a-workflow-that-starts-outside-of-Slack)

실제 팀원에게 시험 알림은 보내지 않았다. 앱 저장·발송 요청·preview 결과와 실제 Slack 수신/버튼 클릭은 구분해 확인한다.

워크플로 입력 방법·복사할 본문·받는 사람·버튼 설정은 [Slack 설정 가이드](SLACK-RETAKE-WORKFLOW-GUIDE.md)를 따른다. 댓글과 리테이크가 같은 워크플로를 사용하므로 공용 버튼은 `B flow에서 확인하기`를 권장하고, 리테이크 전용 문구는 가이드의 선택 분기로 설정한다.

## 검증

- `npm run typecheck`: renderer 및 Electron 타입 검사 통과.
- `npm run build:vite`: Slack 전송 간격과 PR 리뷰의 두 경로 보완까지 포함해 전체 사전 테스트와 renderer/main/preload 빌드 통과. 테스트 2,373개 중 2,345개 통과, 실패 0개, 기존 간트 DB 통합 테스트 28개 건너뜀. 최종 로그는 `.superpowers/verification/retake-feedback/build-review1.log`에 보관.
- 로그인한 로컬 preview에서 캐릭터에 댓글을 추가하고 카드·리스트의 작은 배지 1개 즉시 반영 확인. 댓글이 없는 캐릭터는 배지가 숨겨짐.
- 검증용 리테이크를 생성해 재알림의 테스트 발송·30초 중복 방지 확인. 메인 위젯에서 진행중 → 완료 메모를 포함한 담당 완료 → 기존 허브에서 활성화된 최종 완료 버튼 → 최종 완료됨 표시를 확인.
- 기존 허브 및 세트 허브에서 씬 상세를 열고 닫아 목록·선택 유지 확인. 해당 리테이크가 상세창 안에서 강조되며 BG/ACT 선택도 상세창 안에 유지됨.
- 메인 위젯의 항목을 클릭해 정확한 세트 선택·행 펼침·상세 표시 확인. URI 파싱, 로그인/연결 대기, 조회 실패 재시도, 사용자 변경, 재알림 권한·부분 실패는 자동 회귀 테스트로 확인.
- 독립 코드 검토에서 발견한 DB 정규화 누락, 앱 알림 성공 오판, 생성 중 사용자 변경 문제를 수정한 뒤 재검토 통과.
- 기존 리테이크의 담당 지정·변경에서 새 담당 차집합만 전송, 담당 해제·동일 배정·저장 실패 시 무발송, 세션 변경 차단, preview 동등성을 검증하고 독립 재검토 통과. 이 추가 경로의 앱 알림 문구·이벤트 중복 방지는 자동 테스트로 확인했으며 별도의 실제 Slack 수신 시험은 하지 않음.
- PR 리뷰에서 알림용 사용자 조회가 본문 저장을 막는 경로와 renderer 리스너 준비 전 딥링크 유실 경로를 확인했다. 저장 전 canonical 사용자·세션 캡처와 저장 후 최신 전송 권한·Slack 정보 확인을 분리하고, main/preload의 수신 준비·전달 확인 계약으로 시작·새로고침 중 링크를 보관한다.

실제 Slack workflow 버튼 템플릿 변경·담당자 수신, 설치된 Electron의 OS 프로토콜 실행, 운영 Supabase 다중 계정 동작은 위 로컬 검증에 포함하지 않았다. `build:vite`가 만든 manifest는 설치 파일이 없는 개발용이다. 후속 정식 배포는 머지 커밋에서 `npm run build`로 설치 파일을 생성하고 전체 파일 해시를 검증하며 `manifest.json`을 마지막에 게시한다.

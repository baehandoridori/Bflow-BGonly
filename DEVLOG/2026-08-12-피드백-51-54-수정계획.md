## 2. 아키텍처 전제

- **프로젝트**: B flow — Electron + React 18 + TypeScript + Tailwind + Zustand + Supabase(PostgreSQL + Realtime). 저장소 `C:\Bflow-BGonly` (또는 그 워크트리).
- **필수 명령**: `npm run typecheck`(3개 tsconfig) · `npm run test:<스위트>`(Node 22 내장 `node --test` — vitest 아님) · `npm run build:vite`(테스트 전체 + vite build). 테스트 파일은 `package.json`의 해당 `test:*` 스크립트에 **명시 나열해야 실행된다**.
- **테스트 컨벤션**: `tests/*.test.ts`는 `node --test`가 직접 import — 소스 유틸을 직접 import하는 테스트는 **`@/` alias 금지**(상대경로 + electron 쪽은 `.ts` 확장자 포함 가능 — 기존 `presenceMerge.test.ts`가 `../electron/presence/presenceMerge.ts` 형태). 소스 원문 정규식 앵커 테스트가 다수 — 코드를 바꾸면 해당 앵커도 같이 갱신해야 한다(각 작업의 테스트 절 참조). **앵커는 "항목 존재"만 고정하고 목록 끝(`>>`, `)`)을 고정하지 말 것** — 목록이 자라면 반드시 깨진다.
- **IPC 단일 경로**: 렌더러에서 Supabase 직접 호출 금지. 렌더러 → preload(`window.electronAPI`) → main(ipcMain) → `electron/supabase.ts`.
- **electron 소스 간 import는 확장자 없이** (`import ... from './workFileIndex'`) — `.ts`를 붙이면 TS5097 에러.
- **낙관적 업데이트**: 데이터 변경은 즉시 UI 반영 → Supabase 동기화 → 실패 시 롤백. (이번 작업 중 데이터 쓰기는 52번의 localStorage뿐이라 해당 없음 — 그룹 접기는 **개인 로컬 상태**이며 DB에 저장하지 않는다.)
- **update-notes 톤**: `DEVLOG/update-notes.json`의 `summary`/`description`은 비개발자 톤 — 기술 용어·식별자·파일 경로 금지, "상황 + 영향 + 결과" 시나리오로. PR 본문의 `📋 업데이트 요약` 섹션도 동일 룰.

### 씬 편집 프레즌스 파이프라인 (작업 3·4의 공통 배경 — 전부 코드로 확인됨)

```
[각 팀원 PC의 B flow main 프로세스]
 mohoWindowPoller (4초 폴링: PowerShell Get-Process *moho* → MainWindowTitle)
   → mohoTitleParser.parseMohoTitles (제목 정규화 → 소문자 basename 목록)   ← 엔티티 무관
   → editingPresenceService.publish
       → sceneLinkIndex (scene_work_links의 primary_file → basename→sceneUuid 인덱스)  ← 씬 전용
       → trackPresence(payload { userId, username, editingSceneUuids, updatedAt })
           = Supabase 'bflow-realtime' 채널에 presence track (클라이언트당 payload 1개)
[모든 클라이언트]
 presence sync/join/leave → receivePresence → mergePresenceState (uuid별 사용자 병합)
   → broadcastSupabasePresence: 모든 창에 IPC 'supabase:presence-event' + lastPresenceSnapshot 캐시
   → 렌더러 App.tsx → useEditingPresenceStore.applyPresenceSnapshot
   → 셀렉터 selectEditorsForScenes / hasSceneCollision (임의 uuid 키에 동작하는 범용 함수)
   → UI: editingBeamClass 등 클래스 헬퍼 + EditingNameLabels + EditingPresenceBanner
        (CSS는 src/styles/scene-effects.css — 전역 로드, 엔티티 개념 없음)
```

핵심 함의 3가지:
1. **폴러·파서·dedupGate·CSS·클래스 헬퍼·표시 컴포넌트·셀렉터는 씬을 모른다** — 무수정 재사용. 씬 의존은 ① basename→uuid 해석(sceneLinkIndex) ② payload 필드명(`editingSceneUuids`) ③ 스냅샷이 단일 평면 맵(`Record<sceneUuid, EditingUser[]>`)이라는 3곳뿐.
2. **presence payload는 클라이언트(연결)당 1개** — `electron/realtime.ts`의 `lastPresencePayload` 단일 변수. 씬 감지와 복장 감지가 **각각** `trackPresence()`를 부르면 서로 덮어쓴다. 반드시 한 publish에서 씬·복장을 모두 해석해 **한 payload로 합쳐 track**해야 한다(작업 3의 구조적 이유). 채널 추가도 금지 — 무료 플랜 연결 수 부담 + 재연결 로직 중복.

# 작업 1 — 항목 53: 카드 복장 넘김을 휠에서 좌/우 버튼으로 교체

## 문제/요청 요약

카드 위에서 휠을 돌리면 복장 썸네일이 넘어가는 기능(피드백 21, B8)이 `preventDefault()`로 페이지 스크롤을 하이재킹한다. 카드가 많아져 스크롤할 일이 늘자 충돌이 체감됨. 작성자가 제안한 2안(작은 좌/우 버튼)을 채택하고 휠 리스너는 제거한다.

## 근거 (파일: `src/components/characters/CharacterCard.tsx`)

휠 리스너 — 55~85행 (앵커 `// B8: 이미지 있는 복장을 카드 위 휠로 순환 미리보기`):

```tsx

  const wheelAccum = useRef(0);
  const lastStepAt = useRef(0);
  useEffect(() => {
    const el = imageRef.current;
    if (!el) return;
    const count = imaged.length;
    // React onWheel 은 passive 라 preventDefault 불가 → native non-passive 로 등록.
    const onWheel = (e: WheelEvent) => {

      e.preventDefault();
      wheelAccum.current += e.deltaY;
      if (Math.abs(wheelAccum.current) < 40) return; // 작은 델타 누적 — 트랙패드 과도 전환 방지.
      // 관성 스크롤 연타 억제 쿨다운.
      if (e.timeStamp - lastStepAt.current < 120) { wheelAccum.current = 0; return; }
      const dir = wheelAccum.current > 0 ? 1 : -1;
      wheelAccum.current = 0;
      lastStepAt.current = e.timeStamp;
      setActiveIdx((i) => ((i + dir) % count + count) % count);
    };
    el.addEventListener('wheel', onWheel, { passive: false });
    return () => el.removeEventListener('wheel', onWheel);
    // compact ⇄ card 왕복 시 이미지 박스 DOM 이 새로 마운트되므로(카드 key 불변 → 리마운트 없음)
```

## 수정 내용

**설계 결정 (실행 에이전트가 임의 판단하지 말 것):**
- 접힘 키는 **`${tab.id}:${group.id}`** (미분류는 `${tab.id}:__ungrouped__`) — 탭이 여러 개라 그룹 id만으로는 충돌 여지가 있고, 미분류는 탭별로 구분해야 하므로 탭 id를 접두한다.
- 접힘 본문은 **조건부 렌더로 제거**한다(트랜지션 없음, chevron 회전만 모션). 그룹 그리드는 높이가 수백~수천 px로 가변이라 태그 행의 `max-h-64` 방식이 통하지 않고, `max-height` 트랜지션 근사값은 레이아웃 점프를 만든다 — 단순함 우선.
- **접힌 섹션에도 카드 드롭 가능** — `onDragOver`/`onDrop`은 `<section>` 요소에 걸려 있어 헤더만 보여도 동작한다(수정 불필요, 검증만).
- **레일에서 접힌 그룹 클릭 시 자동으로 펼친 후 스크롤** — "보러 가기" 의도이므로. 펼침 직후 DOM 반영 전 스크롤을 막기 위해 `requestAnimationFrame`으로 스크롤을 미룬다.
- 삭제된 그룹의 stale 접힘 키는 정리하지 않는다 — 렌더는 존재하는 그룹 키만 참조하므로 무해하고, 다른 탭의 키를 오삭제할 위험이 더 크다. 그룹 수 규모(수십)에서 localStorage 성장은 무시 가능.

```ts
/** 커스텀 탭 그룹 섹션 접힘 키 목록 (피드백 52). 키 형식: `${tabId}:${groupId | '__ungrouped__'}`. */
export function loadPersistedGroupFolded(): string[] {
  try {
    const raw = localStorage.getItem(GROUP_FOLDED_KEY);
    if (!raw) return [];
    const parsed: unknown = JSON.parse(raw);
    return Array.isArray(parsed) ? parsed.filter((v): v is string => typeof v === 'string') : [];
  } catch {
    return [];
  }
}

export function savePersistedGroupFolded(keys: string[]): void {
  try { localStorage.setItem(GROUP_FOLDED_KEY, JSON.stringify(keys)); } catch { /* ignore */ }
}
```

### (a) `electron/presence/workFileIndex.ts` — **신설** (엔티티 무관 인덱스/해석)

```ts
// electron/presence/workFileIndex.ts
// 엔티티 무관 "작업 파일 basename → 소유 엔티티 id" 인덱스 (피드백 54).
// 씬(scene_work_links.primary_file)과 캐릭터 복장(character_costumes.work_file_path)이 같은 알고리즘을
// 공유하며, 이후 다른 엔티티(예: 릴 파일)에 파일 열림 감지를 붙일 때도 이 모듈을 재사용한다.
import path from 'path';

export interface WorkFileEntry {
  /** 이 파일이 열려 있으면 "편집 중"으로 표시할 엔티티의 uuid. */
  id: string;
  path: string | null | undefined;
}

/** path 의 basename(소문자) → id 집합. path 없는 항목은 건너뛴다. */
export function buildWorkFileBasenameIndex(entries: WorkFileEntry[]): Map<string, Set<string>> {
  const index = new Map<string, Set<string>>();
  for (const entry of entries ?? []) {
    if (!entry?.id || !entry.path) continue;
    const base = path.win32.basename(entry.path).toLowerCase();
    if (!base) continue;
    let set = index.get(base);
    if (!set) index.set(base, (set = new Set()));
    set.add(entry.id);
  }
  return index;
}

export interface ResolveIdsResult {
  ids: string[];
  /** 동명 파일이 서로 다른 엔티티 2개+에 걸린 basename 목록(진단 로그용). */
  collisions: string[];
}

/** 열린 basename 목록 → 매칭된 엔티티 id 유니온 + 콜리전 보고. */
export function resolveIdsForBasenames(
  index: Map<string, Set<string>>,
  basenames: string[],
): ResolveIdsResult {
  const idSet = new Set<string>();
  const collisions: string[] = [];
  for (const base of basenames ?? []) {
    const set = index.get(base);
    if (!set || set.size === 0) continue;
    if (set.size > 1) collisions.push(base);
    for (const id of set) idSet.add(id);
  }
  return { ids: [...idSet], collisions };
}
```

```ts
import type { EditingPresencePayload, EditingPresenceSnapshot, EditingUser, PresenceSnapshotBundle } from './types';

type PresenceState = Record<string, EditingPresencePayload[]>;

function mergeUuidField(
  state: PresenceState,
  pick: (p: EditingPresencePayload) => string[] | undefined,
): EditingPresenceSnapshot {
  const byUuidUsers = new Map<string, Map<string, EditingUser>>();
  for (const payloads of Object.values(state ?? {})) {
    for (const p of payloads ?? []) {
      for (const uuid of pick(p) ?? []) {
        let users = byUuidUsers.get(uuid);
        if (!users) byUuidUsers.set(uuid, (users = new Map()));
        if (!users.has(p.userId)) users.set(p.userId, { userId: p.userId, username: p.username });
      }
    }
  }
  const snapshot: EditingPresenceSnapshot = {};
  for (const [uuid, users] of byUuidUsers) snapshot[uuid] = [...users.values()];
  return snapshot;
}

    byScene: mergeUuidField(state, (p) => p.editingSceneUuids),
    byCostume: mergeUuidField(state, (p) => p.editingCostumeUuids),
```

```ts
  const warned = new Set<string>();
  const gate = createDedupGate();

  const publish = (basenames: string[]) => {
    const user = deps.getCurrentUser();
    if (!user) return;
    // 폴러는 1개 — 같은 basename 목록을 씬·복장 인덱스 양쪽으로 해석해 한 payload 로 track 한다.

    const costumeIdx = buildWorkFileBasenameIndex(deps.getCostumeFiles());

    const fresh = collisions.filter((c) => !warned.has(c));
    if (fresh.length) { fresh.forEach((c) => warned.add(c)); deps.logCollision?.(fresh); }
    // 씬·복장 어느 쪽이 바뀌어도 재track — 두 집합을 한 dedup 키로 합친다.
    const key = `${[...sceneUuids].sort().join('|')}#${[...costumeUuids].sort().join('|')}`;

    deps.track({
      userId: user.userId,
      username: user.username,
      editingSceneUuids: sceneUuids,
      editingCostumeUuids: costumeUuids,
      updatedAt: deps.now(),

  };

  const polling = startMohoTitlePolling({ intervalMs: deps.intervalMs, onChange: publish });

    stop: () => polling.stop(),
```

```ts
 *  PostgREST 는 기본 1000행 캡이 있으므로 .range() 페이지네이션으로 전량을 읽는다. */
export async function readCostumeWorkFiles(): Promise<Array<{ id: string; path: string | null }>> {
  const PAGE = 1000;
  const rows: Array<{ id: string; path: string | null }> = [];
  for (let offset = 0; ; offset += PAGE) {
    const { data, error } = await supabase
      .from('character_costumes')
      .select('id, work_file_path')
      .order('id', { ascending: true })
      .range(offset, offset + PAGE - 1);
    if (error) throw new Error(`character_costumes work_file_path 조회 실패: ${error.message}`);
    const page = (data ?? []) as Array<{ id: string; work_file_path: string | null }>;
    rows.push(...page.map((r) => ({ id: r.id, path: r.work_file_path })));
    if (page.length < PAGE) break;
  }
  return rows;
}
```

```ts
// 복장 작업 파일 경로 캐시 — 프레즌스 basename→복장 매칭용 (피드백 54).
let costumeFileCache: Array<{ id: string; path: string | null }> = [];

// 전체 복장 파일 경로를 다시 읽어 프레즌스 캐시를 최신화. 실패 시 기존 캐시 유지.
async function refreshCostumeFileCache(): Promise<void> {
  try {
    costumeFileCache = await sbReadCostumeWorkFiles();
  } catch (err) {
    console.warn('[presence] character_costumes 파일 경로 캐시 갱신 실패:', err);
  }
}

// 이 realtime payload 가 복장 "작업 파일 경로" 캐시에 영향을 주는 변경인지 판정 (피드백 54).
// character_costumes 는 스테이지 토글 등 변경 빈도가 높은 테이블 — 모든 변경에 캐시 재로드+reset 을 걸면
// 토글 1회마다 전 클라이언트가 전량 재조회 + 재track 하는 증폭이 생긴다. path 실변경만 골라낸다.
// 판정이 불가능한 형태(row/old 필드 부재)면 안전 측으로 true(fail-open — 놓치는 것보다 한 번 더 읽는 쪽).
function costumeFileCacheAffected(payload: {
  eventType: 'INSERT' | 'UPDATE' | 'DELETE';
  row: Record<string, unknown> | null;
  old: Record<string, unknown> | null;
}): boolean {
  if (payload.eventType === 'DELETE') {
    // REPLICA IDENTITY 기본값이면 old 에는 id 만 온다 — 캐시에 path 가 있던 행의 삭제만 영향.
    const oldId = payload.old?.id;
    if (typeof oldId !== 'string') return true;
    return costumeFileCache.some((c) => c.id === oldId && !!c.path);
  }
  const row = payload.row;
  if (!row || typeof row.id !== 'string' || !('work_file_path' in row)) return true;
  const nextPath = (row.work_file_path as string | null) ?? null;
  const cached = costumeFileCache.find((c) => c.id === row.id)?.path ?? null;
  return nextPath !== cached;
}
```

## 엣지 케이스 & 주의사항

- **씬·복장 크로스 매칭**: 같은 basename이 씬 링크와 복장 파일 양쪽에 걸리면 **양쪽 다 태깅**한다(어느 쪽 파일이 열렸는지 창 제목만으로 구분 불가 — 안전 측). 씬 파일은 `b###.moho` 패턴, 복장 파일은 캐릭터 이름 기반이라 실제 충돌 확률은 낮다.
- **`editingSceneUuids` 이름·의미 불변** — 구버전 클라이언트 호환의 축.
- `preload.ts`는 무수정 — payload를 `unknown`으로 중계한다.
- `electron/realtime.ts`는 무수정 — `lastPresencePayload`가 `unknown`이라 필드 추가에 영향 없다.

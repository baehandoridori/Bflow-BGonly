  - 시안 ‘팀 제작’의 `공유 3명` 표시와 접기/펼치기를 직접 확인했다. 변경 후 `build:vite` exit 0: 타입 검사·전체 2,094개 테스트·앱 번들 빌드 통과, 실패/취소/생략 0. 로그: `%TEMP%/bflow-gantt-share-count-build.log`.
- 작업·그룹·마일스톤, 작업자·참석자·메모·씬 연결, 자동/수동 선행 일정 계산, 완료/복원과 실행 취소/재실행을 구현했다.
- 이름은 막대 옆, 총 기간은 막대 오른쪽에 표시한다. 날짜만 있으면 양 끝 날짜를 포함하고, 시간이 있으면 실제 경과 일·시간·분, 마일스톤은 0일을 표시한다.
- 세로 격자 없이 공통 테마와 Pretendard를 사용한다. 커서 중심 휠 확대/축소, Shift 가로 이동, 빈 영역 작성, 막대 이동/리사이즈, 우클릭 제목·날짜·메모·색상 편집을 연결했다.
- 빠른 편집의 색상은 다른 입력과 함께 저장한다. 저장 실패와 원격 revision 변경 시 초안을 버리지 않는다. 프로젝트 하나 안의 다중 선택 완료는 한 번에 저장한다.
- 연결 캘린더 이벤트는 간트 작업의 projection이다. 제목·날짜·시간·메모를 양쪽에서 수정하고, 캘린더 삭제는 연결 해제, 간트 작업 삭제는 projection 제거로 처리한다.

- `domain.ts`의 공통 계산 → 낙관적 store → 세션 epoch 검증 IPC → 프로젝트 CAS RPC.
- SQL: `DEVLOG/migrations/2026-09-05-gantt-workspaces.sql`. 폴더 ACL, 프로젝트 제한, 연결 캘린더 권한, requestId 멱등성, 사용자/캘린더 삭제 정리를 포함한다.

## 2026-09-05 작업·그룹 추가 동작 수정

- 재현: 선택한 작업의 프로젝트와 상단 생성 대상이 달라 다른 프로젝트에 작업이 생겼다. 그룹 선택도 생성 위치에 반영되지 않았고, 프로젝트/폴더 저장은 수정한 항목을 목록 마지막으로 옮겼다.
- 선택 상태와 생성 대상을 하나로 연결했다. 그룹 선택 후 작업 추가는 그 그룹의 하위로, 작업 선택 후 추가는 같은 단계 바로 다음으로 삽입한다. 그룹 추가는 선택 항목 다음의 같은 단계에 만들며, 새 그룹이 다음 작업의 생성 대상이 된다.
- 상단과 상세 패널의 하위 작업 추가는 같은 시작일·위치 계산을 사용한다. 저장 중에는 선택한 프로젝트를 유지하고 추가만 비활성화한다. 보기 전용 프로젝트에서 다른 프로젝트로 우회 생성하지 않는다.
- 기존 프로젝트/폴더 저장은 원래 목록 위치를 유지한다. 빈 그룹은 임의의 기간 막대를 표시하지 않으며, 하위 작업이 생긴 뒤 기간과 선행 일정 계산에 참여한다.
- 회귀 검사는 수정 전 실패를 확인하고 수정 후 통과했다. 생성 UI 7개, 목록 순서 및 preview 재조회 2개, 빈 그룹 계산 2개를 추가했다.
- 최종 `npm.cmd run build:vite`: **exit 0**, 타입 검사와 renderer/main/preload 빌드 통과. 전체 **2,094 pass / 0 fail / 0 cancelled / 0 skipped**, 간트 **72 pass**. PGlite SQL 실행 검사도 포함했다. 로그: `%TEMP%/bflow-gantt-creation-build.log`.
- 사용자 in-app preview `http://127.0.0.1:4320/?preview=1`에서 기존 ‘새 그룹’ 하위 작업 생성, 새 그룹→하위 작업 연속 생성, ‘레이아웃 확인’과 ‘키 배경 제작’ 사이 작업 삽입, 빈 그룹 기간 안내와 프로젝트 순서 유지를 직접 확인했다. 확인용으로 만든 항목만 실행 취소했으며 기존 시안 데이터는 유지했다.

# 오푸스에게 붙여 넣을 프롬프트 — 씬 댓글 B안 구현 (2026-11-04)

아래 가로줄 사이를 그대로 복사해 새 세션에 붙여 넣는다. 세션은 `C:\Bflow-BGonly` 에서 연다(워크트리 자동 생성 OK).

B flow(`C:\Bflow-BGonly`, Electron + React + TS) 씬 댓글 기능을 **B안**으로 개편한다. 모든 결정과 스펙은 `docs/superpowers/specs/2026-11-04-scene-comments-b-plan-handover.md` 에 있다. 먼저 그 문서 전체와 `CLAUDE.md`, `AGENTS.md`, `tasks/lessons.md`(댓글·알림 관련 항목)를 읽고, 시안 `docs/superpowers/mockups/2026-11-04-scene-comments-b-plan.html` 을 브라우저로 열어 장면 탭 여섯 개(기본 / 스레드 열림 / 리테이크 스레드 / /re 빠른 리테이크 / 안 읽음 필터 / 댓글 없음)를 다크·라이트 모두 확인한 뒤 시작한다. 점검 보고서는 `docs/superpowers/mockups/2026-11-04-scene-comments-review.html` 이다(근거가 필요할 때만).

진행 규칙:
1. 인수인계서 §11 의 PR 1 → 2 → 3 → 4 → 5 순서로, PR 하나씩 끝낸다. 한 PR 안에서는 커밋을 작은 단위로 나눈다(한글 커밋 메시지). PR 6(메인 프로세스 알림 서비스)은 내가 따로 "진행"이라고 하기 전에는 하지 않는다.
2. 각 PR 마다: `npm run typecheck` → 관련 `test:*` → `npm run build:vite` 를 통과시키고(로그로 확인), 화면을 바꾼 PR 은 `npm run preview:electron` 으로 앱 엔진에서 다크·라이트·패널 폭 320/600·스레드 열림·빈 상태·실패 상태를 확인한다. 내 PC 를 쓰고 있는 동안 보이는 창을 띄우지 않는다.
3. PR 본문은 `pr-creator` 스킬 형식으로 쓰고, '업데이트 요약'과 `DEVLOG/update-notes.json` 은 비개발자 톤(기술 용어·식별자·파일 경로 금지, 상황 → 영향 → 결과 한두 문장)으로 쓴다. 버전은 머지 직전 `origin/main` 의 `package.json` 을 다시 보고 정한다(`package.json`·`package-lock.json` 둘 다).
4. PR 을 열면 `codex-review-loop` 스킬로 코덱스 리뷰를 돌리고 P1/P2 를 반영한다. 코덱스가 명시적으로 OK 하면 **머지까지 진행한다**(merge commit). 코덱스가 한도로 못 돌면 로컬 5축 리뷰(정확성·데이터 안전·접근성·움직임·전송량)로 대체하고 PR 에 적은 뒤 머지한다. 머지 뒤 다음 PR 은 최신 main 에서 새 브랜치로.
5. **배포는 하지 않는다.** `npm run build`·G드라이브 동기화·슬랙 공지는 내가 "배포"라고 말할 때만.
6. 인수인계서 §12 '결정 대기' 네 가지는 적힌 기본값으로 먼저 진행하고, 각 PR 보고에 "기본값으로 진행함"을 한 줄 적는다. 그 밖에 문서에 없는 판단이 필요하면 추측하지 말고 PR 보고에 질문으로 남기고 다음 단계를 계속한다(멈추지 않는다).
7. 보고는 PR 하나가 머지될 때마다: 무엇이 바뀌었는지(비개발자 톤 3줄), 측정값(§7 의 IPC 호출 수), 남은 PR, 결정 대기 질문. 긴 설명·기술 용어는 PR 본문에만.
8. 디자인 원칙: 왼쪽 세로 막대·보라 발광·알약 남발·그림자 카드 금지, 토큰만 사용(하드코딩 색 금지), italic 금지, 글자 10px 미만 금지, 움직임은 transform/opacity 120~180ms 만. 라이트 모드에서 먼저 어색해 보이는 것이 있으면 다크에 맞추지 말고 둘 다 자연스럽게 토큰을 고친다.

시작하면 먼저 인수인계서를 읽고 PR 1(서버 비용)의 작업 계획을 10줄 안으로 보고한 뒤 바로 착수한다.

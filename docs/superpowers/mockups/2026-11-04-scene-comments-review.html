댓글 기능, 지금 어디가 괜찮고 어디가 아마추어틱한가

댓글 UI 한 파일(4,148줄)과 알림이 지나가는 길(렌더러 2곳 + 메인 + 슬랙)을 영역별로 아홉 번 읽고, 지적 하나하나를 세 명의 반박 검증자가 다시 코드로 확인했습니다(에이전트 300개, 약 56분). 아래는 세 질문에 대한 짧은 답이고, 왼쪽 목차의 각 장에 화면 목업과 근거가 있습니다. 한 가지 먼저: 댓글 데이터 자체는 깔끔합니다. 고칠 것은 화면과 알림의 길, 그리고 서버를 불필요하게 깨우는 습관입니다.

① 댓글 가독성 · UI

반쯤 Slack, 반쯤 채팅앱. 답글은 본문 안에 들여쓰기로 전부 펼쳐지는 동시에 오른쪽 '스레드' 창에도 또 그려지고, 댓글·답글·스레드 메시지마다 '답글' 알약이 붙어 있어 "답글의 답글"이 있는 것처럼 보입니다(실제 저장은 전부 루트 아래). 내 글만 오른쪽·보라색, 날짜 구분 없음, 아바타 없음, 글자 9~12px. 리테이크 대화는 스레드로 접히지 않고 최상위 말풍선으로 줄줄이 섭니다.

② 알림 코드

함수가 하나가 아니라 네 벌입니다. "누가 알림을 받나"를 서버가 아니라 받는 쪽 PC가 정하는데, 그 판정이 본 창 안에 두 번(실시간 이벤트용·방송용), 리테이크 댓글용 한 번, 슬랙은 댓글 패널과 리테이크 카드에 복제돼 있습니다. 답글의 상대를 @멘션 배열에 넣어 알림을 만들기 때문에 답글마다 슬랙이 한 통씩 갑니다. 캐릭터 댓글의 @멘션은 아무에게도 가지 않고, 댓글을 고치거나 지우면 모든 PC가 씬 데이터를 통째로 다시 받습니다. 알림이 쌓이는 건 50개 캡·로그인마다 담당 리테이크 재주입·설정 토글 하나가 멘션까지 끄는 것이 겹친 결과입니다.

③ 추천 방향

B안(Slack 그대로) + 알림 서비스 한 곳. 본문에는 원댓글과 '답글 N개' 한 줄만, 답글은 스레드 창에서만. 리테이크는 리테이크 카드 하나를 루트로. 알림은 메인 프로세스의 댓글 알림 서비스 하나가 수신자 계산 → 알림 저장 → 방송 → 슬랙까지 맡고, 렌더러는 '내 알림이 왔다'만 그립니다.

이번 점검에서 확인된 것

세 질문에 대한 답, 조금 더 길게

1. 댓글 가독성

구조는 이미 Slack 모델(루트 + 1단계 답글)입니다. 데이터는 깔끔하고, 답글의 답글을 눌러도 항상 루트 아래로 저장되게 잘 막아 두었습니다. 문제는 그 규칙이 화면에 드러나지 않는 것입니다. 답글 아래에 또 '답글' 버튼이 있으니 사용자는 중첩이 되는 줄 알고 누르는데, 결과는 '@이름' 멘션만 붙은 평범한 답글이라 어색함이 생깁니다. 같은 답글이 본문과 스레드 창 두 곳에 동시에 보이는 것, 내 글만 오른쪽에 붙는 것, 리테이크 대화만 접히지 않는 것이 "사람이 만든 UI" 인상을 깎는 세 가지입니다. 상세는 지금 화면의 문제, 고친 모습은 제안 A·B·C.

2. 알림

멘션 슬랙은 정상적으로 나갑니다(작성자 PC → 메인 → 슬랙 워크플로, 수신자 1명당 1건, 1.1초 간격, 429만 재시도). 스레드 안에서 @태그해도 같은 길을 탑니다. 다만 '누구에게'를 정하는 코드가 네 군데이고 서로 조금씩 다릅니다. 리테이크 카드 안에서 쓴 댓글은 요청자를 자동 멘션하지 않아 슬랙이 안 가고, 댓글 패널 스레드에서 쓴 똑같은 댓글은 갑니다. 답글은 상대를 자동으로 @멘션 처리해 저장하므로 답글마다 슬랙이 한 통씩 가고 제목은 '태그했습니다'로 뜹니다. 작성자 본인에게 슬랙 ID가 없으면 아무에게도 안 가며, 실패는 콘솔에만 남습니다. 슬랙 메시지의 EP·파트 표기도 'EP.01 A파트'와 'EP02 A' 두 형식이 섞여 나갑니다. 알림이 쌓이는 문제는 세 가지가 겹친 것입니다. 알림 센터가 종류별로만 묶어 같은 씬 댓글 5개가 5줄로 보이고, 50개 캡을 단순 절단해 씬 변경 알림이 멘션을 밀어내며, 로그인할 때마다 담당 리테이크 최대 50개가 알림으로 다시 들어옵니다. 상세는 알림이 가는 길과 알림 센터 제안.

3. 추가 제안

댓글이 이미 "리뷰 지시"로 쓰이고 있으니 해결됨 표시, 안 읽은 스레드만 보기, 댓글을 팀 할 일로 보내기, 스레드 팔로우/끄기, 씬 단위 알림 묶음을 제안합니다. 각각의 비용과 모습은 워크플로 제안에.

① 댓글 UI · 현안

지금 화면 그대로, 문제 지점에 번호를 붙였습니다

아래 패널은 미리보기 앱에서 뽑은 실제 DOM 클래스와 치수(폭 456px, 말풍선 12px, 답글 11.5px, 알약 24px)로 다시 그린 것입니다. 댓글 위에 마우스를 올리거나 '답글'을 눌러 보면 지금 앱과 같은 동작을 합니다. 오른쪽 목록의 항목에 마우스를 올리면 해당 지점이 커집니다.

· '답글'을 누르면 지금처럼 오른쪽에 스레드 창이 열립니다
번호가 가리키는 것
  1. 답글 진입점이 둘 — 말풍선 옆 호버 아이콘과 항상 떠 있는 '답글' 알약. 한 화면에 같은 버튼이 10개 넘게 반복됩니다.
  2. 답글 아래에 또 '답글' — 눌러도 루트 아래에 저장되고 '@이름'만 붙습니다. 사용자는 중첩 스레드가 생기는 줄 압니다.
  3. 같은 답글이 두 곳에 — 본문 들여쓰기 블록(기본 펼침)과 오른쪽 스레드 창에 동시에 그려집니다.
  4. 내 글만 오른쪽·보라 — 스레드 창에서는 다시 왼쪽. 같은 댓글이 자리와 모양을 바꿉니다. 호버 아이콘 위치도 좌/우로 달라집니다.
  5. 리테이크 대화는 안 접힘 — re#1 댓글이 전부 최상위 말풍선으로 서고, 왼쪽 2px 선과 [re1] 칩으로만 묶임을 표시합니다. 같은 사람이 이어 써도 묶지 않습니다.
  6. 활동 카드가 댓글보다 무거움 — 리테이크 등록/진행/완료가 그림자 카드 + 버튼 3개. 평평한 말풍선 사이에서 시각 무게가 역전됩니다.
  7. 날짜 구분·아바타 없음, 글자 9~12px — 연속 댓글은 시간이 아예 사라지고(호버 표시 미구현), 본문 12px·메타 11px이라 위계가 눌립니다.
  8. 're만'·'활동 감추기' — 내부 용어. 처음 보는 팀원은 re가 뭔지 모릅니다.

그 밖에 코드에서만 보이는 것: 입력 카드의 '답글 모드'(보라 테두리 + "…의 스레드에 댓글 추가")는 켜질 수 없는 죽은 코드 약 100줄, 안 쓰는 라이트박스 컴포넌트 145줄, '수정됨' italic(레포 규칙 위반), 호버 전엔 안 보이는 수정·삭제 버튼에 키보드 포커스·aria-label 없음.

알림이 가는 길: 지금은 네 벌, 제안은 한 벌

"댓글을 쓰면 알림이 간다"는 한 문장이 코드에서는 아래처럼 갈라집니다. 색이 있는 상자가 같은 규칙을 따로 들고 있는 곳입니다.

알림이 쌓이고 새는 이유 — 코드에서 확인한 것

답글마다 슬랙이 간다 P2

답글의 상대(원댓글 작성자·리테이크 요청자)를 @멘션 배열에 몰래 넣어 알림을 만듭니다. 그래서 스레드에서 "네 확인했어요" 열 번 주고받으면 상대 슬랙에 열 통이 가고, 앱 알림 제목도 '답글'이 아니라 '나를 태그했습니다'로 뜹니다. 저장된 데이터로는 직접 @와 자동 멘션을 구분할 수 없습니다.

토글 하나가 멘션까지 끈다 P2

설정의 '내 씬 댓글 알림'(설명: 배정된 씬에 댓글이 달리면)이 실제로는 @멘션·답글·리테이크 등록/진행/완료 알림까지 모두 끕니다. 시끄러워서 끈 사람은 자기를 부른 알림도 못 받습니다. 반대로 반응·배정·피드백은 끌 방법이 없습니다.

50개 캡 + 리테이크 재주입 P2

알림은 최대 50개를 단순 절단합니다. 누가 내 씬 체크박스를 20개 바꾸면 20줄이 들어와 사흘 전 안 읽은 멘션이 밀려 사라집니다. 게다가 로그인할 때마다 '미완료 담당 리테이크' 최대 50개가 알림으로 다시 들어와(지워도 부활) 목록을 점령합니다.

'놓친 알림 N개'가 거짓으로 뜬다 P2

멘션의 '마지막으로 본 시각'이 실시간 수신 때 갱신되지 않아(피드백·배정·반응은 갱신됨) 매 로그인마다 전 세션 멘션을 다시 조회하고 토스트를 띄웁니다. 그 조회는 댓글 테이블을 최대 2,000행(이미지 주소 포함) 긁습니다.

같은 댓글에 토스트 두 번 P3

실시간 이벤트와 방송 두 길로 오는 같은 댓글을 3초 창으로만 거릅니다. 연결이 느려 3초 넘게 벌어지면 목록은 1줄이지만 토스트와 Windows 알림은 두 번 뜹니다.

죽은 설정 셋 P3

'알림 소리'는 읽는 곳이 없고, '동기화 완료 알림'은 참조 0, '표시 시간'은 알림 토스트가 8초 고정이라 무시됩니다. 설정을 바꿔도 아무 변화가 없어 설정 화면을 믿지 않게 됩니다.

멘션이 이름 글자로 저장 P3

@멘션은 사용자 id가 아니라 이름 문자열 배열입니다. 이름을 바꾸면 과거 멘션 복구가 끊기고, 성이 같은 두 사람이 생기면 서로의 알림을 받을 수 있습니다(지금 팀 규모에선 드묾).

댓글을 고쳐 @를 넣으면 아무 데도 안 간다 P2

"아 @아무개 빠뜨렸다" 하고 수정해 태그를 넣는 흔한 행동에서 슬랙 호출도, 앱 알림(INSERT만 처리)도 없습니다. 작성자는 보냈다고 믿습니다.

리테이크 스레드의 @는 종이 안 울린다 P2

리테이크 댓글에서 받은 @멘션은 종류가 '리테이크'로 들어가 '나를 부른 알림' 규칙(종 흔들림·안 읽은 멘션 수)에서 빠집니다. 같은 @인데 어디서 받았느냐로 세기가 다릅니다.

알림 본문에 #태그 원문이 노출 P2

슬랙 쪽은 #씬·#파트 태그를 걷어내고 보내지만 앱 토스트·알림 창·Windows 알림은 저장 형식 그대로("[#A파트](bpart:3f9c…") 보여 주고 50자에서 UUID 중간을 자릅니다.

미리보기·테스트가 못 잡는다 P1

미리보기 앱은 댓글을 써도 방송·실시간 이벤트를 흉내 내지 않아 알림 수신 판정이 한 번도 돌지 않습니다(테스트 알림 버튼은 완성된 알림을 바로 넣음). 수신자 판정 모듈의 단위 테스트는 0개이고, 댓글 테스트 4개는 어떤 npm 스크립트에도 등록돼 있지 않아 빌드가 실행하지 않습니다.

알림이 쌓이는 문제: 종류별 묶음에서 씬·스레드별 묶음으로

지금 알림 센터는 '씬 알림 2건 · 리테이크 알림 3건'처럼 종류로 묶습니다. 그래서 같은 씬 스레드에서 오간 댓글 다섯 개가 다섯 줄이 되고, 리테이크 하나의 등록·진행·완료가 세 줄이 됩니다. 제안은 씬(스레드) 단위로 한 장, 그 안에 최근 두세 줄 미리보기, 그리고 '스레드 열기 · 읽음 · 이 스레드 알림 끄기' 세 동작입니다.

  • 내 씬 댓글 알림 — 설명은 '배정된 씬에 댓글'이지만 실제로는 멘션·답글·리테이크까지 전부 끔

  • 알림 소리 — 저장만 되고 재생 코드 없음(죽음)

  • 표시 시간 — 알림 토스트는 8초 고정이라 무시됨(죽음)

  • 반응 알림 — 기본 꺼짐, 묶어서 표시
  • Windows 알림 · 토스트 위치 — 유지. 소리·표시 시간·동기화 완료는 제거

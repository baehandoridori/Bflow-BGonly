## 1. 배경 & 목적

협업이 본격화되면서 한솔(매니저)이 보고한 6가지를 정리한다. 두 개는 즉시 고쳐야 할 버그, 네 개는 **댓글·이미지 협업** 축에서 부족했던 기능이다.

### 보고된 문제 6가지

1. **씬 추가 시 이미지 첨부하면 "씬 UUID를 찾을 수 없음" 오류** — 씬은 만들어지지만 스토리보드/가이드는 빈 채로 남음
2. **통합 뷰에서 씬 1개 선택 → 삭제 확인창에 "2개 삭제"** — 사용자가 보는 단위(머지드 카드)와 카운트가 어긋남
3. 댓글에 **이모지 리액션이 없음** — 슬랙처럼 가볍게 "확인" / "좋아요" 표시할 방법이 없어 댓글이 과해짐
4. 라이트박스 이미지에 **다운로드/복사 동작이 없음** — 외부 도구로 가져갈 때 마우스 우클릭이 막혀 있음
5. **이미지 "교체" 동작이 비파괴적이지 않음** — 이전 그림을 잃어 회고/되돌리기가 어려움
6. **그림 위에 빠르게 표시할 도구가 없음** — 컴포지팅 피드백을 글로만 적느라 시간이 오래 걸림

### 목적

- 협업 도구의 기본기를 채운다: **이모지 리액션 + 우클릭 메뉴 + 비파괴 버전 관리 + 인-앱 드로잉**.
- "교체"를 "버전 추가"로 자연스럽게 진화시켜 **이미지 히스토리**가 항상 남게 한다.
- 드로잉 결과는 자동으로 새 버전으로 떨어져 **버전 시스템과 한 흐름**으로 묶인다.

## 3. 버그 fix 상세

### 3.1 버그 1 — 씬 추가 시 이미지 첨부하면 "씬 UUID를 찾을 수 없음"

**증상**: 통합 모드에서 스토리보드/가이드 이미지를 붙여넣고 씬을 추가하면, 토스트 두 개가 동시에 뜸:
```
✓ 씬 a001 추가 완료 (BG+액팅)
! 수정 실패: Error: 씬 UUID를 찾을 수 없음: EP03_E_BG[31]
! 수정 실패: Error: 씬 UUID를 찾을 수 없음: EP03_E_ACT[31]
```
씬은 만들어지지만 이미지는 빈 채로 남는다.

**근본 원인** ([src/views/ScenesView.tsx:3115-3137](../../../src/views/ScenesView.tsx:3115))
1. `handleAddScene`이 `addSceneOptimistic`으로 로컬 씬 추가 — 이때 `id`(UUID) **없음** ([src/stores/useDataStore.ts:300-309](../../../src/stores/useDataStore.ts:300))
2. `await addScene()` 호출로 Supabase에 INSERT
3. `syncInBackground()`로 진짜 UUID를 다시 받아 store에 채움 — **비동기, 미완료 가능**
4. 동시에, 이미지 업로드를 위한 IIFE가 백그라운드로 떨어짐:
   ```ts
   (async () => {
     const url = await saveImage(images.storyboard, sheet, sceneId, 'storyboard');
     handleFieldUpdateForSheet(sheet, latestIndex, 'storyboardUrl', url);
   })();
   ```
5. `handleFieldUpdateForSheet` → `updateSceneField` → `resolveSceneUuid(sheetName, sceneIndex)` — **이 시점에 store의 옵티미스틱 씬은 `id`가 비어있을 수 있다** → `throw new Error('씬 UUID를 찾을 수 없음...')` ([src/services/supabaseService.ts:258-264](../../../src/services/supabaseService.ts:258))

`syncInBackground()`가 끝나기 전에 `saveImage`가 먼저 끝나면 100% 재현된다. 통합 모드(BG+액팅)에서 두 번 동시 호출되어 두 토스트가 뜬다.

**Fix 전략** — 두 가지 방어선:
1. **인덱스 기반이 아니라 sceneId(human) 기반으로 UUID 재해석.**
   - `handleFieldUpdateForSheet`가 이미지 업로드 콜백 안에서 호출될 때만큼은 `resolveSceneUuidBySceneId(sheetName, sceneId)`를 쓰도록 분기.
   - sceneId(예: "a001")는 옵티미스틱 추가 시점부터 store에 있기 때문에 안전.
   - 단, `resolveSceneUuidBySceneId`도 `scene.id`가 없으면 throw → 그래서 (2)도 같이.

2. **store에 UUID가 도착할 때까지 짧게 폴링 (최대 ~2초).**
   - 새 함수: `waitForSceneUuid(sheetName: string, sceneId: string, timeoutMs = 2000): Promise<string | null>`
   - 100ms 간격으로 store를 polling, UUID 채워지면 즉시 resolve.
   - 타임아웃이면 명확한 토스트: "씬 추가는 됐지만 이미지 동기화 실패. 새로고침 후 직접 첨부해주세요."

이미지 업로드 IIFE는:
```ts
(async () => {
  const uuid = await waitForSceneUuid(targetSheet, sceneId);
  if (!uuid) {
    sonnerToast.error('이미지 업로드 동기화 실패. 새로고침 후 다시 시도해주세요.');
    return;
  }
  const url = await saveImage(images.storyboard, targetSheet, sceneId, 'storyboard');
  await window.electronAPI.supabaseUpdateSceneField(uuid, 'storyboardUrl', url);
  useDataStore.getState().updateSceneByUuid(uuid, { storyboardUrl: url });
})();
```

UUID 기반 직접 IPC를 쓰면 `resolveSceneUuid`를 거치지 않으므로 race 자체가 사라진다.

### 3.2 버그 2 — 벌크 삭제 카운트가 "1개"인데 "2개"로 표시

**증상**: 통합 뷰에서 씬 카드 1장을 선택하고 삭제 → 확인창에 "2개의 씬을 삭제하시겠습니까?". 사용자: "1개만 골랐는데 왜 2개?"

**근본 원인** ([src/utils/bulkOperations.ts:23-56](../../../src/utils/bulkOperations.ts:23))

통합 뷰에서 카드 1장 선택은 `selectedSceneIds`에 `bg:<mergedKey>` + `act:<mergedKey>` **두 개를 모두** 넣는다 ([src/views/ScenesView.tsx:4092](../../../src/views/ScenesView.tsx:4092)). `resolveSelectedUuids`는 각각의 UUID를 반환 → 길이 2. DB row 단위로는 정확하지만, **사용자 모델은 카드 1장**.

**Fix 전략** — 카운트는 머지드 단위, 동작은 그대로:
1. 새 함수 `countSelectedScenes(selectedIds, allMergedScenes, fallbackPart)`:
   - 통합 모드: `mergedKey`로 dedup해서 카운트
   - 개별 모드: 그대로 unique sceneId 카운트
2. `handleBulkDelete` (and 다른 bulk 액션의 사용자 facing 메시지):
   ```ts
   const sceneCount = countSelectedScenes(selectedSceneIds, allMergedScenes, currentPart);
   const isUnified = selectedDepartment === 'all';
   const suffix = isUnified ? ' (BG·액팅 양쪽 적용)' : '';
   const ok = await ConfirmDialog.show({
     message: `씬 ${sceneCount}개를 삭제하시겠습니까?${suffix}`,
     ...
   });
   ```
3. 단, **BG만 또는 액팅만 가진 머지드 씬**도 있다. 머지드 카운트는 동일하게 1, 접미사도 동일 ("양쪽 적용") — 한쪽만 있어도 표현은 일관되게 유지(파스트라가 너무 길어짐). 실제 DB delete는 존재하는 row만 정상 수행.
4. 같은 패턴을 **벌크 단계 토글 / 길이 변경 / 필드 편집** 확인창에도 적용 (현재는 confirm 없이 진행되거나 카운트 표시 부분만 있음 — 영향 받는 곳 식별 후 일괄 fix).

## 4. 기능 #1 — 댓글 이모지 리액션

### 4.1 데이터 모델

새 테이블 `comment_reactions`:
```sql
CREATE TABLE comment_reactions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  comment_id UUID NOT NULL REFERENCES scene_comments(id) ON DELETE CASCADE,
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  emoji TEXT NOT NULL,                         -- "✅", "👍", "❤️", "👀", "🎉", "🙏", "🔥" 등 유니코드
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (comment_id, user_id, emoji)          -- 한 사용자가 같은 이모지 중복 X
);

CREATE INDEX idx_comment_reactions_comment ON comment_reactions(comment_id);
CREATE INDEX idx_comment_reactions_user ON comment_reactions(user_id);
```

RLS: 모든 인증 사용자 SELECT/INSERT/DELETE 가능 (본인 user_id에 한해).

마이그레이션 파일: `DEVLOG/migrations/2026-05-15-comment-reactions.sql`

### 4.2 UI / UX

**위치**: 각 댓글 본문 아래 (이미지/멘션 행과 같은 레벨, 그 아래).

**렌더링**:
- 그룹화된 칩(이모지+카운트) 가로로 나열, "+" 버튼이 끝에.
- 본인이 누른 이모지는 액센트 색(보더+텍스트) 강조 (CSS `.reaction-chip.active`).
- 칩 호버 → 누가 눌렀는지 툴팁 ("박정인, 김단비, 나 — 누른 사람: 3명"). 첫 3명 + 추가 카운트.
- "+" 버튼은 평소 0.5 opacity, 댓글 hover 시 1.0. 클릭 시 빠른 7개 + 더보기 피커.

**상호작용**:
- 칩 클릭 = 본인 리액션 토글 (옵티미스틱).
- 풀 피커 = 슬랙스러운 그리드. 1차에선 카테고리 없이 single-page 70여 개 (이후 emoji-mart 검토).
- 시스템 이벤트("...가 LO 완료") 행에는 리액션 비활성.

**노티 정책 (1차)**: 댓글 작성자에게도 리액션 알림 전송 X (소음 우려). v1.27에서 옵션 추가 검토.

| 이미지 복사 | `navigator.clipboard.write([new ClipboardItem({'image/png': blob})])`. PNG로 변환 후 클립보드. | Ctrl+C |
| 이미지 URL 복사 | Supabase Storage CDN URL을 텍스트로 클립보드 복사 | — |
| (구분선) | | |
| 주석 새 버전으로 그리기 | 드로잉 모드 진입 (기능 #4) | — |

### 5.3 구현

`ImageModal.tsx`에:
- `onContextMenu={(e) => { e.preventDefault(); openCtxMenu(e.clientX, e.clientY); }}`
- 우상단 ⋯ 버튼 추가 (기존 툴바 옆)
- 커스텀 컨텍스트 메뉴 컴포넌트 (Portal로 렌더링, body click 시 닫힘)
- 메뉴 동작 후 미니 토스트로 결과 안내 ("저장됨", "복사됨")

다운로드:
```ts
const blob = await (await fetch(imageUrl)).blob();
const a = document.createElement('a');
a.href = URL.createObjectURL(blob);
a.download = generateFileName(...);
a.click();
URL.revokeObjectURL(a.href);
```

복사 (PNG 변환):
```ts
const img = new Image();
img.crossOrigin = 'anonymous';
img.src = imageUrl;
await new Promise((res) => img.onload = res);
const canvas = document.createElement('canvas');
canvas.width = img.naturalWidth; canvas.height = img.naturalHeight;
canvas.getContext('2d')!.drawImage(img, 0, 0);
canvas.toBlob(async (blob) => {
  await navigator.clipboard.write([new ClipboardItem({'image/png': blob!})]);
}, 'image/png');
```

`drive-img://` 레거시 프로토콜 이미지는 fetch 직접 안 됨 — Electron `webContents` 또는 IPC로 우회 (메인 프로세스에서 디스크 읽어 blob 반환).

## 6. 기능 #3 — 이미지 버전 관리 (시안 A+B 결합)

### 6.1 데이터 모델

새 테이블 `scene_image_versions`:
```sql
CREATE TABLE scene_image_versions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  scene_id UUID NOT NULL REFERENCES scenes(id) ON DELETE CASCADE,
  image_type TEXT NOT NULL CHECK (image_type IN ('storyboard', 'guide')),
  version_no INT NOT NULL,                            -- 1부터 시작, 씬+타입별 시퀀스
  url TEXT NOT NULL,                                  -- Supabase Storage URL
  kind TEXT NOT NULL CHECK (kind IN ('replace', 'annotate')),  -- 교체 / 주석
  base_version_no INT,                                -- 주석이면 어느 버전 위에 그렸는지 (nullable)
  created_by UUID NOT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (scene_id, image_type, version_no)
);

CREATE INDEX idx_scene_image_versions_scene_type ON scene_image_versions(scene_id, image_type, version_no DESC);
```

기존 `scenes.storyboardUrl` / `scenes.guideUrl`은 **항상 최신 버전의 URL**이 들어가도록 유지 (외부 표시·기존 코드 호환). 마이그레이션 시 기존 URL을 `version_no = 1, kind = 'replace'`로 한 줄씩 백필.

마이그레이션: `DEVLOG/migrations/2026-05-15-scene-image-versions.sql`

### 6.2 UI / UX (시안 A+B 결합)

**라이트박스 UI 추가 영역**:

```
┌─────────────────────────────────────────────────┐
│ [v2 한솔 5/14 ▾]               (툴바 …) [✕]   │  ← 좌상단 드롭다운 트리거 (B)
│                                                  │
│              [ 이미지 영역 ]                       │
│                                                  │
├─────────────────────────────────────────────────┤
│ [v1] [v2★] [v3주석] [+]    v2 · 한솔 · 5/14    │  ← 하단 썸네일 스트립 (A)
└─────────────────────────────────────────────────┘
```

**좌상단 드롭다운 (B)**:
- 닫힘 상태: `[v2  한솔 · 5/14  ▾]` 칩 1줄.
- 열림 상태: 목록 — 각 항목에 썸네일/이름/타입 배지/작성자·시간/(삭제 버튼).
- 항목 클릭 = 그 버전으로 메인 이미지 전환.
- 삭제 버튼은 hover 시 노출, **작성자 본인 + 관리자만** 활성. 클릭 시 ConfirmDialog.

**하단 썸네일 스트립 (A)**:
- 가로 스크롤. 각 썸네일 64×48px.
- 우상단 노란 코너 = 주석 버전 표시.
- "현재" 배지(좌상단) = 메인 이미지에 표시 중인 버전.
- "+" 버튼 = 파일 선택 + 새 교체 버전 업로드.
- 우측 끝에 작은 메타 (`v2 · 한솔 · 5/14 · 교체`).

**드롭다운/스트립 동기화**:
- 한쪽에서 버전 선택하면 다른 쪽도 즉시 currentVersion 표시 갱신.
- 라이트박스 닫고 다시 열면 → 최신 버전부터 시작 (selectedVersion은 기억하지 않음).

**외부 표시**: 항상 최신 버전. `scenes.storyboardUrl` / `scenes.guideUrl`이 최신 버전 URL 반영.

**버전 추가**:
- 스트립 "+" 버튼 = 파일 선택 → 업로드 → `kind = 'replace'` 버전 추가
- 드로잉 저장 = `kind = 'annotate'`, `base_version_no = 현재` 버전 자동 추가

### 6.3 동작 시나리오

| 시나리오 | 결과 |
|---|---|
| 사용자가 빈 씬에 처음 이미지 업로드 | v1 생성, 외부 표시 = v1 |
| 사용자가 "+ 버전 추가"로 다른 이미지 업로드 | v2 생성 (kind=replace), 외부 표시 = v2, 라이트박스도 v2 보임 |
| 사용자가 v2 위에 주석 그리고 저장 | v3 생성 (kind=annotate, base=2), 외부 표시 = v3 |
| 사용자가 v1을 라이트박스에서 선택 후 닫음 | 외부 표시는 여전히 v3 (가장 최신) |
| 작성자가 v2 삭제 | v2 row 삭제. 외부 표시는 그대로 v3 (최신). v3.base_version_no=2는 그대로 유지 (참조 정보용, FK 강제 X) |
| 비작성자/비관리자가 삭제 시도 | 삭제 버튼 비활성. RLS도 막음 (defense in depth) |
| 모든 버전 삭제 | 마지막 1개는 삭제 불가 (서버 측 가드) — 빈 이미지 상태로 만들려면 "씬 이미지 비우기" 별도 액션 필요(이번 범위 아님) |

### 6.4 IPC / 서비스

`storageService.ts` 또는 새 `imageVersionService.ts`:
```ts
export async function listImageVersions(sceneId: string, imageType: 'storyboard' | 'guide'): Promise<ImageVersion[]>
export async function addImageVersion(sceneId: string, imageType: 'storyboard' | 'guide', kind: 'replace' | 'annotate', file: Blob | string, baseVersionNo?: number): Promise<ImageVersion>
export async function deleteImageVersion(versionId: string): Promise<void>
```

서버에서 새 버전 추가 시:
1. 같은 (scene_id, image_type)의 max(version_no) + 1 계산
2. 파일을 Supabase Storage에 업로드 (`scene-images/{sceneId}/{imageType}_v{N}.jpg`)
3. `scene_image_versions` row INSERT
4. `scenes.{imageType}Url`을 새 URL로 갱신 (max(version_no)인 경우만)
5. Realtime broadcast

기존 `saveImage()`와 `replaceImage()` 경로는 새 함수를 호출하도록 thin wrapper로 유지 (호환).

## 7. 기능 #4 — 드로잉 주석 툴

### 7.1 진입

1. **라이트박스 툴바**에 "주석" 버튼 추가 — 클릭 시 캔버스 오버레이 활성
2. **우클릭 메뉴 → 주석 새 버전으로 그리기**

진입 시 표시 중인 버전이 base가 됨. 진입과 동시에 다른 모든 툴바 동작 비활성 (시점/줌/이전 다음 등) — 주석 모드를 명확히 구분.

### 7.2 캔버스 구조

```
[ 원본 이미지 (HTMLImageElement 또는 CSS background) ]
[ 투명 캔버스 (HTMLCanvasElement, 같은 픽셀 크기, 위에 absolute) ]
[ 상단 도구 툴바 (floating) ]
[ 하단 옵션 바 (color/stroke/opacity, floating) ]
[ 우상단 [취소] [주석 새 버전으로 저장] ]
[ 좌하단 메타: "대상: v2 위에 그리는 중 · 저장 시: v3 (주석) 자동 생성" ]
```

캔버스 크기 = 이미지 실제 픽셀 크기(고해상도 보존). CSS는 컨테이너에 fit. 마우스 좌표를 픽셀 좌표로 변환해 그림 그리기.

### 7.3 도구 동작

| 도구 | 동작 |
|---|---|
| 펜 (하이라이터) | `mousedown` → `mousemove`로 path 그리기. `globalAlpha = opacity * 0.5` (반투명 기본). `lineCap='round'`. |
| 직선 | `mousedown` 스냅샷 → `mousemove`에서 스냅샷 복원 + 임시 선. `mouseup`에 확정. |
| 화살표 | 직선 + 끝점에 화살촉 (angle 기반 두 줄). |
| 사각형 | 직선 패턴 + `strokeRect`. |
| 원 | 직선 패턴 + `ellipse`. |
| 텍스트 | `mousedown`에 `prompt('텍스트를 입력하세요:')` → `fillText(text, x, y)`. 굵기에 따라 `font-size = width * 4`. |
| 지우개 | 펜과 동일하지만 `globalCompositeOperation = 'destination-out'`. 원본 이미지에는 영향 X (캔버스 레이어만). |

### 7.4 색상 / 굵기 / 투명도

색상 7개 (디자인 토큰 기반):
- `#EB5757` (danger) — 빨강 (오류 표시 기본)
- `#FDCB6E` (review) — 노랑 (강조)
- `#00B894` (png) — 초록 (OK 표시)
- `#74B9FF` (lo) — 파랑
- `#A29BFE` (done) — 보라
- `#FFFFFF` — 흰색 (어두운 이미지 위)
- `#0F1117` — 검정 (밝은 이미지 위)

굵기: S(2px) / M(4px) / L(8px)
투명도: 20~100%, 슬라이더

### 7.5 단축키

| 키 | 동작 |
|---|---|
| Ctrl+Z | 실행 취소 (toDataURL 스택 기반, 최대 50단계) |
| Ctrl+Shift+Z | 다시 실행 |
| Esc | 주석 모드 종료 (변경 있으면 confirm) |
| Delete | "모두 지우기" (confirm 필요) |

### 7.6 저장

"주석 새 버전으로 저장" 클릭 시:
1. 새 캔버스에 원본 이미지를 그리고 그 위에 주석 캔버스를 합성 (`drawImage`)
2. `toBlob('image/jpeg', 0.9)`로 JPEG 변환 (Supabase Storage 정책과 일치)
3. `addImageVersion(sceneId, imageType, 'annotate', blob, currentVersionNo)` 호출
4. 외부 표시 갱신 → 자동으로 `v(N+1) (주석)`이 최신 버전이 됨
5. 라이트박스에서 새 버전을 메인으로 전환하고 주석 모드 종료
6. 성공 토스트: "주석 v3 저장됨"

### 7.7 동시 편집 정책 (1차)

**1차 정책**: 단일 사용자 편집 (Liveblocks 미사용). 두 명이 동시에 주석 모드 진입 → 둘 다 각자의 캔버스에 그리고 각자 저장하면 v3, v4가 차례로 생성. 한 명이 저장한 결과는 다른 명에게 Realtime으로 들어오지만 다른 명의 진행 중 캔버스에는 자동 반영 X. v1.27에서 충돌 감지/Live 협업 검토.

### 10.5 이미지 버전 관리

- [ ] "+" 버튼으로 새 이미지 업로드 → v2, 외부 표시 = v2
- [ ] 드롭다운에서 v1 선택 → 라이트박스만 v1, 외부 표시는 여전히 v2
- [ ] 드롭다운 메타 정확 (작성자/시간/타입)
- [ ] 본인이 올린 v1 삭제 가능
- [ ] 다른 사람이 올린 v1 삭제 버튼 비활성 (관리자는 가능)

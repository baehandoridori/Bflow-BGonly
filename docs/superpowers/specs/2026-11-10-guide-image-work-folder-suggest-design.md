# 가이드 그림을 넣을 때 작업 폴더 제안 — 설계

- 날짜: 2026-11-10
- 요청: 한솔
- 상태: 검토 반영(2026-11-10 빌더 점검 질문 4개 → 한솔 답 3개 + 코드 확인 1개)
- 시안: 대화 중 띄운 움직이는 시안(배치 C '아래에서 올라옴', 테마 강조색 버튼)을 이 문서의 화면 기준으로 삼는다.

> 표기 — **[결정]** 은 한솔이 정한 것, **[내 판단]** 은 설계자가 정한 것(틀렸으면 고칠 수 있음), **[구현자 몫]** 은 만드는 사람이 정해도 되는 것.

---

## 1. 왜 만드나

배경 씬의 가이드 그림은 대부분 공유 드라이브의 씬 작업 폴더 안에 있다(예: `…\d파트\d054\d054가이드.png`). 팀원은 그 그림을 탐색기에서 끌어다 B flow 씬 상세 창의 **가이드** 칸에 넣는데, 같은 폴더를 '작업 링크 › 작업 폴더' 칸에 따로 다시 찾아 넣어야 한다. 그래서 배경 작업 폴더가 저장된 씬은 운영 DB 기준 14개뿐이다(액팅은 285개).

가이드 그림을 넣는 순간, 앱이 그 그림이 있는 폴더를 알아서 찾아 "이 폴더를 작업 폴더로 넣을까요?"라고 제안하면, 한 번 누르는 것으로 작업 폴더(와 대표 파일)가 채워진다.

### 성공의 모습
- 끌어다 놓기·탐색기로 고르기로 가이드 그림을 넣으면 거의 항상 맞는 폴더가 제안되고, 버튼 한 번에 저장된다.
- 경로가 없는 '그림만' 붙여넣기도 같은 파트에 저장된 폴더가 있으면 맞는 폴더를 찾아 준다.
- 틀린 제안으로 방해하지 않는다 — 확실하지 않으면 아무것도 띄우지 않는다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 배경 씬 상세 창의 **가이드** 칸에 그림을 넣을 때 그 씬의 배경 **작업 폴더** 를 제안한다. **[결정]**
- 폴더 안 `.clip` 이 확실히 하나로 정해지면 **대표 파일** 도 함께 제안한다. **[결정]**
- 기존 '작업 링크' 저장 길(`scene_work_links`, 부서 `bg`)을 그대로 쓴다. DB 변경 없음. **[내 판단]**

**비목표**
- 스토리보드 칸은 제안하지 않는다. **[결정]**
- '새 씬 추가' 창은 제안하지 않는다(씬 상세 창에서만). **[결정]**
- 액팅 작업 폴더는 다루지 않는다.
- 공유 드라이브 전체를 뒤져 같은 그림을 찾는 기능은 만들지 않는다(구글 드라이브가 파일을 내려받아 매우 느리고 용량을 잡아먹는다).
- 이미 저장된 엉뚱한 경로(예: a003 씬에 b파트 경로)를 고치는 정리 작업.
- 그림 크게 보기 창 안의 '버전 추가(+)'와 주석 저장으로 들어오는 가이드 그림. 버전 기록용 동작이고, 크게 보기 창 위에 또 창을 띄우게 되기 때문이다. **[내 판단]**

**반목표(이렇게 되면 기능이 있어도 실패)**
- 그림 넣기가 느려지거나 막힌다. 제안은 그림 저장을 절대 기다리게 하지 않는다.
- 틀린 폴더를 자신 있게 제안해 팀원이 무심코 잘못 저장한다.
- 이미 맞게 저장된 씬에서 매번 창이 떠 귀찮게 한다.
- 제안 창이 열린 채 씬 상세 창이 닫히거나, Esc 한 번에 둘 다 닫힌다.

## 3. 범위 — 어디서 동작하나

- 가이드 칸이 있는 **모든 배경 씬 상세 창**에서 같은 방식으로 동작한다. 하나의 공용 훅·공용 창으로 붙인다. **[내 판단]**
  - 통합 씬 상세 창 `src/components/scenes/UnifiedSceneDetailModal.tsx`(가운데 모드·옆에 붙인 모드, 컴포지팅 현황판의 씬 창이 이걸 감싸 씀)
  - 부서 하나 씬 상세 창 `src/components/scenes/SceneDetailModal.tsx`
  - 나의 할 일 위젯의 씬 창(`src/components/widgets/my-tasks/components/SceneDetailModal.tsx`)은 가이드를 넣는 기능이 없는 간이 창이라 대상이 아니다.
  - 위젯 팝업 창(별도 창)에서는 위 두 씬 상세 창이 열리지 않는다(2026-11-10 확인). 나중에 팝업 창에서 열게 되면, 팝업 창은 작업 링크 변경 신호를 받지 않으므로 4.5 의 '실시간 다시 판정'을 그 창에 따로 이어 줘야 한다.
- 넣는 방법: **끌어다 놓기**, **탐색기로 고르기**, **Ctrl+V** **[결정]**, 그리고 부서 하나 씬 상세 창의 **'클립보드 붙여넣기' 버튼**(경로 없이 그림만 읽는 길 — 짐작 길로 보낸다, **[결정]**).
  - 옆에 붙인 모드는 지금도 Ctrl+V 를 받지 않는다(기존 동작) — 그대로 둔다.

## 4. 동작 흐름

### 4.1 그림 경로 얻기

| 넣는 방법 | 경로 | 얻는 법 |
|---|---|---|
| 끌어다 놓기 | 있음 | `window.electronAPI.getPathForFile(file)` (Electron 33, 이미 preload 에 있음) |
| 탐색기로 고르기(`<input type=file>`) | 있음 | 같은 `getPathForFile` |
| Ctrl+V — 탐색기에서 '파일 복사' | 있음 | 메인이 클립보드 `FileNameW` 를 읽어 이미지 파일 경로를 돌려줌(`electron/clipboardFiles.ts` `clipboardImageFilePath` 재사용, 새 IPC 하나) |
| Ctrl+V — '그림만' 복사(포토샵·캡처) | 없음 | → 4.3 '짐작' 길 |
| '클립보드 붙여넣기' 버튼(부서 하나 씬 창) | 없음 | → 4.3 '짐작' 길 **[결정]** |
| 브라우저·슬랙 등에서 끌어다 놓기 | 없음(`getPathForFile` 이 빈 값) | → 4.3 '짐작' 길 **[결정]** |

- 그림 저장(기존 `uploadImage`)은 지금처럼 그대로 진행하고, 제안 판정은 **나란히** 돈다. 제안 판정이 그림 저장을 기다리게 하거나 막지 않는다. **[결정: 넣자마자 바로]**
- 그림 저장이 실패해도 제안 창은 그대로 두고, 이미 넣은 경로도 되돌리지 않는다. **[결정]**
- 제안 창이 뜨는 시점은 판정이 끝난 순간이다(경로가 있으면 거의 즉시, 짐작 길은 폴더 목록을 읽는 만큼).

### 4.2 경로가 있을 때

1. 그림 경로가 `G:\공유 드라이브\` 로 시작하는지 본다. 드라이브 글자 대소문자·`/` 와 `\` 차이는 무시한다. 시작하지 않으면 **아무것도 띄우지 않는다**(안내도 없음). **[결정]**
2. 제안 폴더 = 그림 파일이 들어 있는 폴더(바로 위 폴더). **[결정: 그림은 작업 폴더 바로 안에 있다]**
3. 그 폴더 이름에 **씬 번호가 아예 없으면**(4.4 기준 — 예: `d050.052\png` 안, `d파트` 바로 안, 레퍼런스 폴더) **최대 두 단계 위까지 거슬러 올라가** 씬 번호가 든 첫 폴더를 제안 폴더로 삼는다(예: `…\d050.052\png\x.png` → `…\d050.052`). 두 단계 안에 없으면 **아무것도 띄우지 않는다.** 올라가는 동안 `G:\공유 드라이브\` 밖으로 나가지 않는다. **[결정 + 두 단계·멈춤 조건은 내 판단]**
4. 제안 폴더 이름에 씬 번호는 있는데 **이 씬 번호가 없으면**(예: d055 씬에 `d054` 폴더) 노란 경고를 붙여 제안한다(막지 않음 — 같은 배경을 같이 쓰는 씬이 있다). **[결정]**
5. 4.5(저장된 값과 비교) → 4.6(대표 파일) → 제안 창.

### 4.3 경로가 없을 때 — 같은 편 다른 씬을 보고 짐작 **[결정]**

1. **파트 폴더 찾기**
   - 같은 파트(같은 에피소드·같은 파트 글자의 배경 파트)에서 배경 작업 폴더가 저장된 씬들을 모은다.
   - 각 경로의 바로 위 폴더 이름이 `{파트글자}파트`(대소문자 무시, 예: `d파트`·`D파트`)인 것만 쓴다 — 잘못 저장된 경로를 걸러내기 위해. 남은 것 중 가장 많이 나온 위 폴더를 파트 폴더로 정한다. **[내 판단]**
   - 같은 파트에 쓸 만한 경로가 없으면, 같은 에피소드의 다른 배경 파트 씬 경로에서 두 단계 위 폴더(예: `…\배경_싱크홀`)를 구하고, 그 안에서 `{파트글자}파트` 폴더(대소문자 무시)를 찾는다. **[내 판단]**
   - 그래도 없으면 **아무것도 띄우지 않는다.** **[결정]**
2. **씬 폴더 찾기** — 파트 폴더의 하위 폴더 목록(한 단계만, 파일 내용은 읽지 않음)에서 이름에 이 씬 번호가 든 폴더를 고른다(4.4).
   - 0개(아직 안 만듦 등) → **아무것도 띄우지 않는다.** **[결정]**
   - 1개 → 그 폴더를 제안.
   - 2개 이상 → 제안 창에서 고르게 한다. 이름에 든 씬 수가 가장 적은 폴더(예: `d043.046` 이 `d028.043.046` 보다 먼저)를 미리 골라 두고, 같은 수면 이름순. **[결정 + 정렬 기준은 내 판단]**
3. 4.5 → 4.6 → 제안 창. 제안 창 설명은 넣은 방법에 맞춘다(5.2): 붙여넣기는 "붙여넣은 그림이라 경로가 없어서, 같은 파트 다른 씬들을 보고 찾았어요.", 끌어다 놓기는 "끌어다 놓은 그림에 경로가 없어서, 같은 파트 다른 씬들을 보고 찾았어요." **[결정]**

**같은 파트 씬들의 작업 폴더 읽기**: 이 짐작은 드문 동작(가이드 칸에 '그림만' 붙여넣기)에서만 돈다. 해당 파트(와 필요하면 같은 에피소드 배경 파트들)의 씬 uuid 로 기존 `readSceneWorkLinks` 를 **한 번에** 부른다 — 씬마다 한 건씩 부르지 않는다(CLAUDE.md, 2026-10 서버 과부하 사고). `.in()` 이 길어지면 URL 길이로 조용히 깨지므로 기존 나눠 읽기 도우미(`src/shared/postgrestPaging.ts`)를 거친다. 앱이 켜져 있는 동안 파트별로 결과를 기억해 다시 읽지 않아도 된다. **[구현자 몫: 기억 방식]**

### 4.4 폴더 이름에서 씬 번호 읽기 **[내 판단 — 실제 드라이브 확인 근거]**

실제 이름 예(241 싱크홀 대축제 d파트): `d054`, `d050.052`, `d013,015`, `d020.025.045.048`, `d021.024.029.033.035.037.042.044`, `d022.024a`, `d061,063`. 안쪽 폴더 예: `png`, `png_052`. 위쪽 폴더 예: `d파트`, `배경_싱크홀`, `241_싱크홀 대축제`.

- **새 규칙을 만들지 않고** 이미 있는 파일 이름 읽기 규칙 `src/utils/sceneFileNameList.ts`(`readSceneNameLists`·`sceneListForScene`·`sceneRefKey`, '한꺼번에 연결' v1.134.0 이 쓰는 것, 원칙 "틀린 목록보다 묻지 않기")을 쓴다. 번호 견주기도 거기 규칙(`normalizeSceneIdKey` 가족 글자)을 따른다.
- 다만 **폴더 이름에는 확장자가 없으므로 `.` 도 `,` 처럼 나눔표로 읽는다**(읽기 전에 `.` 을 `,` 로 바꾸는 식). `d050.052` → d050, d052. `d022.024a` → d022, d024a.
- **'씬 번호가 든 폴더' = 이 씬의 파트 글자(가족 글자, 예: `d`)로 시작하는 목록이 이름에 있는 폴더.** 글자 없는 숫자만 있는 이름(예: `241_싱크홀 대축제` 의 241)이나 다른 글자 목록(예: `png_052` 의 png)은 씬 번호로 보지 않는다 — 거슬러 올라가기(4.2-3)가 에피소드 폴더 번호를 씬 번호로 잘못 잡지 않게. **[내 판단]**
- `.clip` 파일 이름(4.6)은 기존 규칙을 **그대로**(`.` 를 나눔표로 바꾸지 않고) 읽는다 — 이어서 뜨는 '한꺼번에 연결'(4.7)이 같은 파일을 같은 목록으로 읽게. **[내 판단]**
- 단위 테스트로 위 예를 모두 고정한다(특히 `d024` ≠ `d024a`, `png_052`·`241_…` 은 씬 번호 아님).

### 4.5 저장된 값과 비교 **[결정]**

| 지금 작업 폴더 | 제안 폴더와 | 동작 |
|---|---|---|
| 비어 있음 | — | '새로 넣기' 창 |
| 있음 | 같음 | **아무것도 하지 않음**(대표 파일이 비어 있어도 띄우지 않음 — **[내 판단]**) |
| 있음 | 다름 | '바꾸기' 창 — 지금 경로(줄 그음) → 새 폴더 |

- '같음' 비교는 대소문자·`/`·`\`·끝 `\` 차이를 무시한다. **[내 판단]**
- 후보가 여럿인 짐작 결과에서 지금 작업 폴더가 후보 중 하나면 '같음'으로 본다. **[내 판단]**
- 창이 열린 뒤 다른 팀원이 실시간으로 이 씬의 작업 폴더를 바꾸면, 창 내용을 새 값 기준으로 다시 판정한다(같아지면 창을 조용히 닫고, 달라지면 '바꾸기' 모양으로). '넣기'를 누른 순간에도 최신 값을 다시 확인한다. **[내 판단]**
- 이 창은 기존 `saveWorkLinkPathGuarded` 를 거치지 않고 스토어 `upsertLink` 를 직접 부른다 — 그 길의 확인 창(`ConfirmDialog`)과 자체 알림("작업 링크를 연결했습니다")이 제안 창·성공 알림과 겹치지 않게. 제안 창 자체가 그 확인이다. **[내 판단]**

### 4.6 대표 파일 함께 제안 **[결정]**

- 이 씬의 배경 대표 파일이 **비어 있을 때만** 보여 준다. 이미 있으면 건드리지 않고 체크도 보여 주지 않는다.
- 제안 폴더 안(한 단계, 파일 이름만)의 `.clip` 파일(확장자 대소문자 무시) 중:
  - 하나뿐 → 그것.
  - 여럿 → 이름에서 씬 번호를 읽어(4.4 규칙, 예 `d052.clip`) 이 씬 번호가 든 것이 **딱 하나**면 그것.
  - 그 밖 → 대표 파일 제안 없음.
- 창에 '대표 파일로도 연결 · d054.clip' 체크를 **켜 둔 채** 보여 준다.
- 짐작 길에서 후보 폴더를 바꿔 고르면 대표 파일도 그 폴더 기준으로 다시 고른다. **[내 판단]**

### 4.7 저장

- '작업 폴더에 넣기'/'바꾸기' → 작업 폴더(`bg`, `folder`) 저장, 체크가 켜져 있으면 대표 파일(`bg`, `primary_file`)도 저장. 기존 스토어 `useSceneWorkLinkStore.upsertLink` 길을 쓴다(메인 → Supabase, 낙관적 반영·실패 시 되돌림).
- 저장 중에는 긍정 버튼이 '저장 중'으로 바뀌고 다시 눌리지 않는다.
- 성공 → 창이 내려가며 닫히고, 작업 링크 칸(바뀐 칸만)이 강조색으로 잠깐 빛나고, 오른쪽 아래 작은 알림: "작업 폴더를 넣었어요"(바꾸기면 "작업 폴더를 바꿨어요"). **[결정]**
- 실패 → 창을 닫지 않고 창 안에 "저장하지 못했어요. 인터넷 연결을 확인하고 다시 눌러 주세요." 를 보이고, 긍정 버튼을 '다시 시도'로 바꾼다. **[결정]**
- 작업 폴더는 저장됐는데 대표 파일만 실패하면, 다시 시도는 대표 파일만 저장한다. **[내 판단]**
- **대표 파일까지 저장됐으면, 제안 창이 닫힌 뒤 기존 '한꺼번에 연결'(같은 파일을 쓰는 다른 씬에도 연결할까요?, v1.134.0)을 이어서 띄운다.** **[결정]** 기존 `offerBulkWorkLink` 를 그대로 부르고(기다리지 않음), 성공 알림 id 를 `savedToastId` 로 넘긴다. 작업 폴더만 저장했을 때는 띄우지 않는다(그 기능은 대표 파일 전용).
  - AGENTS.md '씬 작업 링크 한꺼번에 연결' 첫 줄("제안은 `saveWorkLinkPathGuarded` 의 성공 줄 뒤 한 곳에서만")을 이 창을 두 번째 시작점으로 넣어 고친다. 두 곳이 같은 조건(대표 파일일 때만, 기다리지 않음)을 지키도록 한다.
- 누가 저장할 수 있나 — 지금 작업 링크를 고칠 수 있는 사람과 같다(새 권한 없음). 작업 링크 칸이 잠긴 경우('씬 데이터 없음' 등)에는 창을 띄우지 않는다. **[내 판단]**

### 4.8 건너뛰기·끄기

- '건너뛰기'/'그대로 두기' 또는 Esc → 아무것도 저장하지 않고 닫는다. 다음에 가이드 그림을 다시 넣으면 다시 판정한다(기억하지 않음). **[내 판단]**
- **바깥(흐린 곳)을 눌러도 닫히지 않는다.** **[결정]**
- 개인 설정에 스위치 하나: '가이드 그림을 넣을 때 작업 폴더 제안', 처음엔 켜짐. 설정 창에만 두고 제안 창에는 안내를 넣지 않는다. **[결정]** 값은 `preferences.json`(PC 단위 개인 설정)에 둔다. 설정 화면의 '작업 환경' 묶음 아래 어울리는 곳에 둔다. **[구현자 몫: 정확한 위치]**

### 4.9 창이 떠 있는 동안

- 제안 창은 창 전체를 덮는 겹(뒤를 어둡게 + 흐리게) 위에 뜨고, 그동안 씬 상세 창은 누를 수 없다. 씬 넘기기 단축키(화살표 등)·씬 창 닫기 단축키도 막힌다. **[내 판단]**
- 창이 떠 있는 동안 가이드 칸에 그림이 또 들어올 수는 없다(뒤가 막혀 있음). 만약 다른 길로 새 판정이 오면 창 내용을 새 판정으로 바꾼다. **[내 판단]**
- 씬 상세 창이 다른 이유로 닫히면(예: 씬이 지워짐) 제안 창도 함께 닫는다. **[내 판단]**

### 5.3 움직임
- 열림: 뒤 겹은 투명도 0→1(약 180ms, `--ease-out`), 시트는 아래에서 위로(transform, 약 320ms, `--ease-out`) + 투명도.
- 닫힘: 시트는 아래로(약 180ms, `--ease-in`), 겹은 투명도 → 0. 닫힌 뒤 흐림을 끈다.
- 실패 때 시트가 좌우로 살짝 흔들린다(약 260ms).
- **움직임 규칙(CLAUDE.md v1.128.0) 지키기**: transform/opacity 만 움직인다. 흐림(`backdrop-filter`)은 화면에 하나만 있는 정지된 겹에만 쓰고 **흐림 크기를 애니메이션하지 않는다**(겹의 투명도만 바꾼다). 반복·움직이는 요소에는 흐림을 쓰지 않는다.
- '움직임: 최소'·OS 동작 줄이기 → **흐림·어둡게는 그대로, 올라오는/흔들리는 움직임만 없이 바로 나타난다.** **[결정]** CSS 에서는 `[data-motion-minimal]` 존재 속성만 쓴다.

### 5.4 키보드·접근성
- 열리면 초점은 긍정 버튼. Enter = 초점이 있는 버튼 실행(처음엔 긍정 버튼). Esc = 건너뛰기. **[결정: Enter 넣기·Esc 건너뛰기]**

## 6. 기술 구조 **[내 판단 — 구현자가 더 나은 구조로 바꿔도 됨]**

- **메인 프로세스(새 IPC, 렌더러는 파일 시스템 직접 접근 없음)**
  - `clipboard:read-image-file-path` — `FileNameW` 에서 이미지 파일 경로만 돌려줌(없으면 null). 기존 `clipboardImageFilePath` 재사용.
  - `work-folder:list-subfolders(path)` — 한 단계 하위 폴더 이름 목록.
  - `work-folder:list-files(path, ext)` — 한 단계 파일 이름 목록(`.clip`).
  - 모두 구글 드라이브가 느리거나 끊긴 경우를 위해 **시간 제한**(기존 `path:exists` 는 1.5초)을 두고, 넘으면 '없음'으로 돌려준다 → 제안하지 않음. 오류는 콘솔 경고만, 화면에는 아무것도 띄우지 않는다.
  - 입력 경로가 `G:\공유 드라이브\` 밖이면 메인에서도 거절한다(아무 폴더나 훑는 통로가 되지 않게).
  - preload 에 노출, `src/types/index.ts` 타입, **미리보기 mock(`src/mocks/devElectronAPI.ts`)에도 같은 동작**(예시 폴더 구조)을 넣는다.
- **렌더러**
  - 순수 함수(테스트 대상): 공유 드라이브 경로 판정, 경로 같음 비교, 씬 번호 읽기(4.4), 파트 폴더 고르기(4.3-1), 후보 정렬, `.clip` 고르기(4.6), 표시용 경로 줄이기, 판정 결과(띄움/안 띄움/어떤 모양) 결정.

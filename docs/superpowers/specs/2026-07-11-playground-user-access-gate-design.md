# 배플레이그라운드 배한솔 전용 접근 설계

## 목표

배플레이그라운드를 `main`에 포함하되, 초기 실사용 기간에는 로그인 사용자의 이름이 정확히 `배한솔`인 경우에만 노출한다. 허용되지 않은 사용자는 사이드바 메뉴를 볼 수 없고, 저장된 화면 상태나 직접적인 뷰 전환으로 접근을 시도해도 대시보드로 돌아간다.

## 선택한 접근

이름 기반의 작은 허용 목록을 단일 접근 판정 함수로 관리한다.

- 초기 허용 목록: `배한솔`
- 허용 조건: 현재 로그인 사용자의 canonical `name` 값이 허용 목록과 정확히 일치
- 로그인 전, 로그아웃 상태, 이름 누락, 다른 이름은 모두 차단하는 fail-closed 방식
- 기존 개발/배포 환경 변수는 사용자 권한을 우회하지 않는다. `main` 빌드에서도 배한솔은 접근할 수 있고 다른 사용자는 개발 환경에서도 접근할 수 없다.

사용자 ID 고정은 더 엄격하지만 현재 요청이 이름을 기준으로 했고 정확한 ID를 별도로 관리해야 한다. 원격 관리자 설정은 초기 테스트 범위보다 복잡하므로 사용하지 않는다.

## 구조

`src/features/playground/featureFlag.ts`에 사용자 이름만 입력받는 순수 접근 판정 함수를 둔다. 사이드바, 앱 라우트 보호, 몰입형 레이아웃이 모두 이 함수를 사용해 서로 다른 판정을 만들지 않도록 한다.

1. `Sidebar`
   - 배한솔에게만 `배플레이그라운드` 메뉴를 표시한다.
   - 사용자 전환 시 메뉴 목록이 즉시 다시 계산된다.
2. `App`
   - 현재 뷰와 로그인 사용자 이름을 함께 검사한다.
   - 허용되지 않은 사용자가 `playground` 상태를 갖고 있으면 화면 렌더 전에 `dashboard`로 해석하고 저장 상태도 대시보드로 교정한다.
3. `MainLayout`
   - 허용된 배한솔이 실제로 Playground에 있을 때만 전용 몰입형 레이아웃을 사용한다.
   - 다른 사용자가 잠깐이라도 일반 헤더 없는 빈 화면을 보지 않게 한다.

## 사용자 전환과 예외 처리

- 배한솔이 Playground를 보고 있는 동안 로그아웃하거나 다른 사용자로 바뀌면 다음 렌더에서 즉시 대시보드로 이동한다.
- 다른 사용자가 저장된 기본 화면으로 `playground`를 가지고 있어도 로그인 전에는 대시보드로 안전하게 정리한다.
- 권한 판정에는 네트워크 요청이 없으므로 로딩·오류 UI는 추가하지 않는다.

## 테스트

TDD로 다음 순서대로 검증한다.

1. 순수 함수 테스트를 먼저 추가해 기존 코드에서 실패하는 것을 확인한다.
   - `배한솔` 허용
   - 다른 이름, `null`, `undefined`, 비문자열 차단
   - 개발 환경이나 이전 preview 환경 변수만으로는 우회 불가
2. 라우트 테스트
   - 배한솔의 `playground`는 유지
   - 다른 사용자와 비로그인의 `playground`는 `dashboard`
   - 알려지지 않은 뷰는 기존처럼 `dashboard`
3. 배선 테스트
   - Sidebar, App, MainLayout이 모두 같은 접근 판정 함수를 사용
4. 전체 검증
   - `npm run test:playground`
   - `npm run typecheck`
   - `npm run build:vite`
5. 실제 프리뷰
   - 배한솔 로그인에서 메뉴 노출, 입장 애니메이션, A 로비 진입 확인
   - 비허용 사용자 상태에서 메뉴 미노출과 직접 접근 차단 확인
   - 콘솔 오류가 없는지 확인

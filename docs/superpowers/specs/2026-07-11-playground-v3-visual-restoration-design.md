# 배플레이그라운드 승인 v3 비주얼 복원 설계

> 작성일: 2026-07-11
> 상태: 방향 승인 완료, 구현 전 명세 검토 대기
> 사용자 선택: 승인된 A안 로비 + C안 JBBJ 하우스 전체 복원

## 1. 문제와 원인

현재 React 프리뷰는 배플레이그라운드의 기능 이름과 이동 경로는 구현했지만, 사용자가 승인한 최종 목업의 시각 구조를 재현하지 못했다.

최종 승인 목업은 다음 파일이다.

- `C:\Bflow-BGonly\.superpowers\brainstorm\1373-1783705059\content\playground-interactions-v3.html`

이 파일은 `.gitignore`의 `.superpowers/` 규칙 때문에 feature worktree에 전달되지 않았다. 이후 구현 계획은 원본의 2열 로비, 대형 게임 아트, 포인트 랭킹, 지갑, 팀 챌린지를 누락하고 `중앙 추천 카드 → 네 카드 → 하우스 버튼`이라는 선형 구조만 기록했다. 테스트도 문구 존재만 확인하여 시각 구조의 이탈을 감지하지 못했다.

이번 작업은 현재 화면에 장식을 덧붙이는 작업이 아니다. 승인 목업의 정보 계층과 공간 구성을 실제 React 화면으로 다시 옮기는 작업이다.

## 2. 기준 자료와 충돌 우선순위

구현 중 판단이 충돌하면 다음 순서로 결정한다.

1. 배플레이그라운드 로비·JBBJ 하우스·게임 준비 화면의 시각 기준은 `playground-interactions-v3.html`이다.
2. 이 문서는 목업을 실제 앱에 이식할 때 필요한 데이터·접근성·반응형 규칙을 정한다.
3. JBBJ 증권의 메인·종목 상세·내 계좌는 기존 `2026-07-11-jbbj-beginner-stock-market-design.md`와 현재 구현을 유지한다.
4. 외부 Visual Lab 설명 영역, 가짜 창 프레임, 목업용 사이드바는 실제 앱에 복제하지 않는다. B flow의 기존 사이드바 안쪽 앱 화면만 이식한다.

재발 방지를 위해 구현 첫 단계에서 최종 승인 HTML을 Git이 추적하는 `docs/superpowers/mockups/` 아래에 복사하여 시각 기준을 저장한다.

## 3. 목표

- 화면을 처음 본 순간 승인된 v3 목업과 같은 배플레이그라운드로 인식되어야 한다.
- A안 로비를 기본 화면으로 사용하고, 상단 버튼과 우측 티저를 통해 C안 JBBJ 하우스로 이동한다.
- 랜덤 추천은 테트리스·스네이크·스도쿠만 대상으로 한다.
- 실제 구현된 JBBJ 증권은 네 번째 빠른 실행 카드와 JBBJ 하우스 게임 도크에 배치한다.
- 현재의 클릭 지점 도트 전환, 증권 기능, 포인트 이체와 주문 계산은 유지한다.
- 큰 화면의 밀도 높은 2열 구성과 작은 화면의 읽기 쉬운 1열 구성을 모두 제공한다.

## 4. 이번 범위에서 하지 않는 것

- 테트리스·스네이크·스도쿠의 실제 게임 로직
- 슬롯머신의 실제 베팅 로직
- 실시간 팀 접속자, 팀 챌린지, 포인트 랭킹 백엔드
- 관리자용 가격·뉴스 조절과 증권 영구 저장
- Supabase·Electron IPC·배포·버전 변경

팀 접속 상태, 다른 팀원의 랭킹과 팀 챌린지는 이번 프리뷰에서 결정적 fixture로 표시한다. 사용자의 이름과 포인트만 현재 앱 상태를 사용한다.

## 5. 화면 구조

### 5.1 Playground 전용 셸

로비, JBBJ 하우스, 게임 준비 화면에는 56px 높이의 로컬 헤더를 유지한다.

- 왼쪽: 뒤로가기 버튼, 현재 화면 제목, 한 줄 설명
- 오른쪽: `JBBJ 하우스 · 4명 접속 중` 버튼, 현재 보유 포인트와 포인트 순위
- 로비에서는 뒤로가기를 숨기고 JBBJ 하우스 버튼을 보인다.
- 하우스에서는 `게임 로비` 뒤로가기를 보인다. 게임 준비 화면에서는 현재 return surface에 따라 `게임 로비` 또는 `JBBJ 하우스` 뒤로가기를 보인다.
- 하우스에서는 중복되는 JBBJ 하우스 버튼을 숨긴다.
- 증권 화면은 기존 `MarketNav`를 사용하므로 Playground 로컬 헤더를 표시하지 않는다.

Playground 셸은 불투명한 전역 카드 배경으로 덮지 않는다. v3의 검은 바탕, 좌상단 보라 방사광, 우상단 민트 방사광이 화면 전체에 이어져야 한다.

### 5.2 A안 기본 로비

콘텐츠 폭이 충분할 때 로비는 다음 2열 구조를 사용한다.

- 왼쪽 `1.72fr`: 환영 문구, 대형 랜덤 추천, 네 개의 빠른 실행 카드
- 오른쪽 `0.68fr`, 최소 220px: 포인트 랭킹, 내 지갑, JBBJ 하우스 활동 티저
- 열 간격 13px, 내부 패딩 16px

왼쪽 상단에는 `PLAY · REST · COMPETE`와 `{현재 사용자 이름}님, 잠깐 놀다 갈까요?`를 표시한다. 오른쪽에는 현재 포인트 순위를 작은 pill로 반복해 빠르게 인지할 수 있게 한다.

### 5.3 대형 랜덤 추천

추천 hero는 최소 높이 240px의 비대칭 카드다. 단순 아이콘 카드가 아니라 게임마다 전용 색, 문구, 기록, 보상과 CSS/SVG 아트를 사용한다.

아래 제목과 기록·보상 문구는 자유 예시가 아니라 v3 레이아웃을 지키기 위한 정확한 fixture다.

| 게임 | 색 | 제목 | 정확한 기록·보상 문구 | 아트 |
|---|---|---|---|---|
| 테트리스 | 민트 | `TETRIS QUICK RUN` | `평균 4분 · 현재 최고 기록 18,420점` / `골드 등급부터 80 포인트를 획득합니다.` | 회전된 블록 보드 |
| 스네이크 | 라벤더 | `SNAKE ONE MORE RUN` | `평균 3분 · 현재 최고 길이 62` / `실버 등급부터 45 포인트를 획득합니다.` | 굽은 뱀 궤적 |
| 스도쿠 | 블루 | `SUDOKU FOCUS MODE` | `평균 6분 · 현재 최고 기록 04:21` / `플래티넘 등급은 120 포인트를 획득합니다.` | 3×3 숫자 아트 |

동작 규칙은 다음과 같다.

- Playground에 한 번 들어올 때 세 게임 중 하나를 고른다.
- A↔C 이동이나 게임 준비 화면에서 돌아와도 같은 추천을 유지한다.
- 세 게임을 무작위 순서로 섞은 shuffle bag을 사용한다. `다른 추천`을 두 번 누르는 동안 세 게임을 모두 한 번씩 보게 하며, 새 bag의 첫 게임도 직전 추천과 같지 않게 한다.
- 추천 변경은 화면 읽기 도구에 조용히 알려준다.
- `바로 플레이`를 누르면 실제 클릭 지점에서 도트 전환을 시작한다.
- hero 전체를 중첩 버튼으로 만들지 않는다. hero는 표현 컨테이너이며 `바로 플레이`, `다른 추천`만 각각 독립된 버튼이다.

### 5.4 빠른 실행 카드

hero 아래에는 같은 줄에 네 개의 카드가 놓인다.

1. 테트리스 — 전용 블록 아이콘, 최고 기록, 등급별 예상 보상
2. 스네이크 — 전용 궤적 아이콘, 최고 길이, 등급별 예상 보상
3. 스도쿠 — 전용 격자 아이콘, 최고 기록, 등급별 예상 보상
4. JBBJ 증권 — 블루 미니 차트 아이콘, 현재 예수금 또는 간단한 투자 안내, `OPEN` 상태

세 게임과 증권 카드는 모두 실제 `<button>`이며 클릭 지점 도트 전환을 사용한다. 게임은 각 게임의 준비 화면으로, 증권은 기존 시장 메인으로 이동한다.

현재 구현된 기능을 우선하기 때문에 v3의 로비 네 번째 `슬롯머신 SOON` 카드는 JBBJ 증권으로 교체한다. 슬롯머신은 JBBJ 하우스 도크에서 `준비 중`으로 유지한다.

### 5.5 포인트 랭킹 레일

오른쪽 레일에는 다음 순서로 표시한다.

1. `포인트 랭킹` 제목과 `현재 잔액 기준` 설명
2. `MY BALANCE` 카드
3. 상위 5명 랭킹 목록
4. 현재 사용자의 행 강조
5. `JBBJ 하우스에서 진행 중` 티저

다른 팀원 fixture는 민지 4,920P, 도윤 3,860P, 서아 2,820P, 유진 2,115P를 사용한다. 현재 사용자는 `useAuthStore.currentUser.name`과 시장 프리뷰 계정의 `walletPoints`를 사용한다. 목록은 매번 다시 정렬하므로 입출금 후 순위와 다음 순위까지의 차이가 함께 갱신된다.

순위는 포인트 내림차순, 동점이면 고정 id의 한국어 오름차순으로 정하고 화면 순번은 정렬 인덱스 + 1을 사용한다. 공동 순위는 만들지 않는다. 사용자가 1위이면 `현재 포인트 1위예요`, 그 외에는 `앞 순위까지 {차이}P 남았어요`, 동점 tie-break 상태이면 `동점이에요 · 이름순으로 표시 중`이라고 안내한다.

포인트 데이터를 아직 불러오지 못했거나 불러오기에 실패했을 때는 0으로 오해할 수 있는 숫자를 만들지 않는다. 헤더와 지갑은 `— P · 순위 계산 중`, 랭킹 레일은 네 teammate 행을 유지한 뒤 현재 사용자 행을 `순위 계산 중`으로 별도 강조한다. JBBJ 하우스 podium은 teammate fixture를 유지하고 현재 사용자 행만 `— P`로 표시한다.

### 5.6 C안 JBBJ 하우스

현재의 한 장짜리 잔액 카드를 제거하고 승인된 소셜 공간을 복원한다.

- 상단: `WELCOME TO JBBJ HOUSE`, `지금, 네 명이 놀고 있어요.`, 온라인 표시
- 왼쪽 대형 카드: `TEAM CHALLENGE` 태그, 테트리스 팀 합계 100,000점 챌린지, 현재 68,400점/68%, 참여 보상 60P
- 오른쪽: 상위 3명 podium과 현재 사용자 순위
- 하단 게임 도크: 테트리스, 스네이크, 스도쿠, 슬롯머신 준비 중, JBBJ 증권

세 게임과 JBBJ 증권은 로비와 같은 이동 규칙을 사용한다. 슬롯머신은 비활성 상태와 준비 중 설명을 함께 보여주며 클릭 가능한 척하지 않는다. 하우스에서 연 게임의 복귀 버튼과 하우스에서 연 증권의 `놀이터로` 종료는 로비가 아니라 JBBJ 하우스로 돌아간다. 로비에서 연 화면은 로비로 돌아간다. 이 return surface를 `PlaygroundView`가 명시적으로 기억한다.

팀 챌린지와 온라인 수치는 프리뷰 fixture이며 실제 팀 활동으로 오인되지 않도록 `프리뷰 챌린지` 보조 문구를 제공한다.

### 5.7 게임 준비 화면

세 게임은 동일한 일반 카드 대신 v3의 게임별 무대를 사용한다.

- 왼쪽: 게임 이름, 보상 규칙, `게임 준비 중` 상태, 현재 return surface로 돌아가는 복귀 버튼
- 오른쪽: 테트리스 보드, 스네이크 그리드, 스도쿠 보드 중 해당 아트
- 실제 시작 버튼은 제공하지 않는다. 구현되지 않은 기능을 동작하는 것처럼 보이게 하지 않는다.

## 6. 시각 시스템

로비·하우스·게임 준비 화면은 글로벌 테마와 관계없이 승인 목업의 의도적인 다크 아케이드 공간으로 표시한다. 기존 B flow 사이드바와 증권 내부 화면의 테마 동작은 변경하지 않는다.

핵심 색은 v3와 동일한 의미로 사용한다.

- 배경 `#0f1117`
- 패널 `#1a1d27`, 보조 패널 `#202431`
- 선 `#2d3041`
- 본문 `#e8e8ee`, 보조 글자 `#8b8da3`
- 보라 `#6c5ce7`, 라벤더 `#a29bfe`
- 민트 `#45e0b5`, 그린 `#00b894`
- 블루 `#74b9ff`, 보상 옐로 `#fdcb6e`

색은 컴포넌트에 반복 하드코딩하지 않고 Playground 전용 semantic CSS 변수로 정의한다. 제목과 본문은 Pretendard를 유지하고, `RANDOM PICK`, 점수, 포인트, 순위처럼 게임 기계의 상태를 표현하는 작은 라벨에만 monospace를 사용한다.

아이콘은 Lucide 또는 직접 만든 CSS/SVG 아트를 사용하며 이모지를 UI 아이콘으로 사용하지 않는다. hover는 테두리·배경·광량만 바꾸고 카드 크기를 확대하여 레이아웃을 흔들지 않는다.

## 7. 전환과 포커스

- B flow 사이드바 → Playground: 기존 클릭 지점 도트 전환과 `지금은 쉬는 시간!` 오버레이 유지
- 로비/하우스 → 게임·증권: 기존 클릭 지점 도트 전환 유지
- 키보드 실행: 버튼 중심점을 도트 시작점으로 사용
- A안 ↔ C안: 도트를 반복하지 않고 240ms 이내의 짧은 fade/slide 사용
- 하우스/게임 → 로비: 짧은 fade/slide와 제목 포커스 복원
- `prefers-reduced-motion`에서는 입자 수를 0으로 하고 기존 계약과 같은 총 220ms의 어두운 crossfade만 사용한다. A↔C의 fade/slide는 0ms로 즉시 완료한다.

도트 전환의 문구와 색은 목표 화면에 따라 정한다.

- Playground 최초 입장: `지금은 쉬는 시간!`
- 테트리스: `BAE PLAYGROUND / LOADING TETRIS`
- 스네이크: `BAE PLAYGROUND / LOADING SNAKE`
- 스도쿠: `BAE PLAYGROUND / LOADING SUDOKU`
- JBBJ 증권: `BAE PLAYGROUND / OPENING JBBJ MARKET`
- cover 배경은 글로벌 테마와 관계없이 `#07090d`, 글자는 흰색과 민트 보조색을 사용한다.

전환 중 중복 입력은 기존 exactly-once 보호를 유지한다. 추천 변경은 화면 전환으로 취급하지 않는다.

## 8. 반응형 규칙

breakpoint는 브라우저 전체 viewport가 아니라 기존 B flow 사이드바를 제외한 `PlaygroundShell` 콘텐츠 컨테이너의 inline size를 기준으로 한다. 셸에 `container-type: inline-size`를 지정하고 container query로 전환한다.

- 컨테이너 폭 971px 이상: v3의 2열 로비와 2열 JBBJ 하우스, 56px 한 줄 헤더, 네 quick card 한 줄 유지
- 컨테이너 폭 620~970px: 한 열로 전환, 우측 랭킹 레일을 숨기고 게임 카드는 2열, 헤더 설명과 접속 인원 문구는 숨기되 포인트·순위는 유지
- 컨테이너 폭 619px 이하: 헤더는 최소 88px의 두 줄 구조로 바꾼다. 첫 줄에는 뒤로가기/제목과 compact JBBJ 하우스 버튼, 둘째 줄에는 전체 폭 포인트·순위 strip을 둔다. 부제와 `4명 접속 중` 문구는 숨긴다. 게임 카드는 2열 compact 형태, 하우스 도크는 1열이다.
- 앱 전체 viewport 1024px에서는 기존 사이드바를 제외한 콘텐츠 폭이 970px 이하가 되므로 한 열 레이아웃을 기대한다.
- 앱 전체 viewport 390px에서도 가로 스크롤이 없어야 한다.
- 200% 확대에서도 핵심 버튼과 텍스트가 잘리지 않아야 한다.

큰 추천 아트는 좁은 화면에서 투명도를 낮추고 텍스트 뒤를 침범하지 않는다. 포인트 숫자는 줄바꿈 대신 자리 축약 또는 header 내부 재배치를 사용한다.

## 9. 접근성

- 모든 실행 요소는 최소 44×44px 터치 영역을 갖는다.
- 포커스 링은 라벤더 3px와 충분한 offset으로 표시한다.
- 카드 전체가 동작하면 실제 `<button>`을 사용한다.
- hero 안에 버튼을 중첩하지 않는다.
- 추천 변경은 `aria-live="polite"`로 알린다.
- 장식용 게임 아트는 화면 읽기 도구에서 숨기고, 카드 이름과 기록은 텍스트로 제공한다.
- 색만으로 `OPEN`, `SOON`, 현재 순위를 구분하지 않는다.
- 숨겨진 반응형 랭킹의 핵심 정보는 상단 포인트·순위에서 계속 제공한다.
- 한국어 본문은 최소 14px, 작은 영문 상태 라벨은 장식 정보에만 제한한다.

## 10. 상태와 데이터 흐름

- `PlaygroundView`가 현재 내부 route, return surface와 세션 shuffle bag을 소유한다.
- `PLAYABLE_GAMES`는 테트리스·스네이크·스도쿠만 포함한다.
- `QUICK_ENTRIES`는 세 게임과 JBBJ 증권을 포함한다.
- `HOUSE_DOCK_ENTRIES`는 세 게임, 슬롯머신 준비 중, JBBJ 증권을 포함한다.
- 사용자 이름은 `useAuthStore`, 포인트는 `useMarketPreviewStore`에서 읽는다.
- 랭킹은 teammate fixture와 현재 사용자 포인트를 합쳐 순수 함수로 계산한다.
- 게임·챌린지·다른 팀원 데이터는 읽기 전용 fixture다.
- 증권 진입 이후의 주문·이체 상태는 기존 시장 store가 그대로 관리한다.

Playground 전용 셸은 시장 store 로딩 실패 때문에 전체 로비를 막지 않는다. 포인트와 순위만 대체 표시를 보여주고 게임·하우스 이동은 계속 허용한다.

## 11. 컴포넌트 경계

- `PlaygroundView`: route, 세션 추천, 전환 정책 조정
- `PlaygroundShell`: 로컬 헤더와 공통 다크 배경
- `PlaygroundHeader`: 뒤로가기, JBBJ 하우스, 포인트·순위
- `PlaygroundLobby`: A안 전체 배치
- `PlaygroundRecommendationHero`: 랜덤 추천 표현과 두 버튼
- `PlaygroundGameCard`: 게임/증권 빠른 실행 카드
- `PlaygroundRankingRail`: 지갑·랭킹·하우스 티저
- `JbbjHouse`: C안 챌린지·podium·게임 도크
- `ComingSoonGame`: 게임별 준비 무대
- 순수 helper: 추천 변경, 랭킹 정렬, route별 전환 정책

표현 컴포넌트는 store에 직접 의존하지 않고 props를 받아 렌더링한다. store 접근은 셸 또는 상위 화면에서 수행하여 테스트와 향후 실제 백엔드 교체를 쉽게 한다.

## 12. 검증 계획

### 자동 검증

- 추천 pool에 JBBJ 증권이 포함되지 않는지 검사
- `다른 추천`이 현재 추천과 다른 게임을 반환하는지 검사
- A↔C 왕복과 게임 복귀 후 추천이 유지되는지 검사
- 현재 포인트 변화에 따라 랭킹과 다음 순위 격차가 갱신되는지 검사
- 로비에 로컬 헤더, hero, 네 quick card, ranking rail, house teaser가 모두 렌더링되는지 검사
- 컨테이너 1200px에서 실제 DOM geometry가 다음을 만족하는지 검사: 로비가 두 grid track, 왼쪽/오른쪽 폭 비율 2.35~2.70, 오른쪽 최소 220px, hero 최소 240px, quick card 네 장의 상단 좌표 차이 2px 이하
- 컨테이너 960px에서 한 grid track과 quick card 2열, 컨테이너 390px에서 두 줄 header와 가로 overflow 없음 확인
- 하우스에 challenge, podium, 다섯 dock entry가 렌더링되는지 검사
- 하우스 전환은 도트를 쓰지 않고 게임·증권 전환은 도트를 쓰는지 검사
- 일반 도트 전환의 목표별 label과 `#07090d` cover, reduced-motion의 0개 입자·220ms crossfade 계약 검사
- nested button이 생성되지 않는지 server-rendered markup으로 검사
- 기존 `test:playground`, `typecheck`, `build:vite` 전체 통과

### 브라우저 검증

- 1440px: v3와 같은 상단 헤더, 1.72:0.68 구조, hero art, ranking rail 확인. 실제 화면 screenshot을 추적된 승인 HTML과 나란히 놓은 비교 이미지를 `docs/superpowers/mockups/`에 저장하여 사용자 확인을 받는다.
- 1024px: 한 열 전환과 2열 quick card 확인
- 390px 및 200% 확대: 가로 스크롤·가려진 버튼·잘린 텍스트 없음
- `다른 추천`을 두 번 눌러 세 추천 게임을 모두 순환하고 아트·정확한 문구·색 변경 확인. 단위 테스트에서는 RNG를 주입하여 shuffle bag 순서를 결정적으로 검증한다.
- 게임·증권 카드마다 실제 클릭 지점에서 도트가 시작되는지 확인
- A↔C는 도트 없이 짧게 전환되는지 확인
- 포인트 입출금 후 로비 포인트와 순위가 갱신되는지 확인
- 시장 메인·종목 상세·내 계좌가 기존 기능과 레이아웃을 유지하는지 회귀 확인
- 키보드 Tab, Enter, Escape, reduced-motion 경로와 콘솔 오류 확인

## 13. 완료 기준

다음 항목을 모두 만족해야 완료로 본다.

- 승인 v3의 로컬 헤더, 대형 hero, 전용 게임 아트, 2열 로비, 포인트 랭킹 레일이 복원되고 1440px 비교 이미지 및 DOM geometry 기준을 통과한다.
- JBBJ 하우스가 팀 챌린지·podium·게임 도크를 갖춘 C안으로 복원된다.
- 세 게임만 랜덤 추천되고 JBBJ 증권은 별도 실행 카드로 노출된다.
- 사용자의 이름과 포인트가 앱 상태를 반영한다.
- 기존 도트 전환과 증권 세 화면의 기능이 깨지지 않는다.
- 1440px, 1024px, 390px, 200% 확대에서 사용 가능하다.
- 자동 검증과 브라우저 검증이 모두 통과한다.
- 최종 승인 목업이 Git이 추적하는 문서 경로에 남아 이후 계획에서도 참조할 수 있다.

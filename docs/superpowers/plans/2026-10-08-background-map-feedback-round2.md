### 배경 화면을 누구에게 열고, 도면은 누가 고칠 수 있게 할까요?

- 관련: F10 / F12 / F13 - who can open the background screen and who can edit / 막는 항목: F10, F12, F13
- 왜: 지금은 배경 메뉴가 한솔님 계정에만 보입니다. 그래서 다른 사람에게 편집을 맡기거나 주석에서 팀원을 태그해도, 그 사람은 화면 자체를 열 수 없습니다. 이 답에 따라 권한 설정 화면을 만들지, 주석과 태그 알림을 언제 켤지가 정해집니다.
- (추천) **팀 전체가 보고, 관리자가 고른 '배경 편집자'만 고치기** — 배경 메뉴가 모든 팀원에게 보이고, 누구나 둘러보고 주석을 남길 수 있습니다. 도면을 고치는 것은 관리자와, 관리자가 설정에서 이름을 체크한 사람만 할 수 있습니다. 앱 전체 관리자 권한을 넘겨주지 않아도 됩니다.
- **팀 전체가 보고, 고치는 건 지금처럼 관리자만** — 배경 메뉴만 팀에 열고 권한 설정 화면은 만들지 않습니다. 편집을 맡기려면 그 사람을 앱 관리자로 올려야 하고, 그러면 계정 관리 같은 다른 권한도 함께 넘어갑니다. 가장 빨리 끝납니다.
- **팀 전체가 보고, 누구나 고치기** — 명단 없이 로그인한 팀원 모두가 도면을 고칩니다. 간단하지만, 실수로 지운 도면은 되살릴 방법이 없고, 두 사람이 같은 도면을 동시에 고치면 늦게 저장한 쪽이 다시 해야 합니다.
- **당분간 한솔님 계정만** — 지금 그대로 둡니다. 편집 권한과 태그 알림은 만들지 않고, 주석은 한솔님 혼자 쓰는 메모로만 먼저 만들 수 있습니다.

### 지정된 '배경 편집자'는 어디까지 고칠 수 있어야 하나요?

- 관련: F10 - what a designated editor may change / 막는 항목: F10
- 왜: 지금 앱은 배경 화면의 편집 권한을 하나의 스위치로 다룹니다. 그대로 쓰면 빨리 끝나고, 도면만 따로 떼면 손볼 곳이 늘어납니다. 첫 번째 질문에서 '편집자 지정'을 고르셨을 때만 해당합니다.
- (추천) **배경 화면 전체 (관리자와 똑같이)** — 도면뿐 아니라 장소 폴더, 배경 이미지 등록, 시점 묶음까지 고칠 수 있습니다. 도면에 밑그림을 올리거나 공간에 장소를 연결하려면 어차피 필요한 권한이라 일하기 편합니다.
- **도면만** — 도면은 고치지만 배경 목록, 이미지 등록, 시점 묶음은 관리자만 고칩니다. 권한을 둘로 나누는 작업이 더 들어갑니다.

### 주석에서 태그된 사람에게 어떻게 알릴까요?

## 4. 저장 내용이 바뀌는 묶음의 배포 규칙

v1.130.0 validates the whole library strictly on every read (src/features/backgrounds/useBackgroundStore.ts:30 -> domain.ts:94-98) and the SQL validator rejects unknown keys and kinds on every write, so stored-data changes roll out as follows. (1) Every change to the stored map shape (B3: symbol kind 'stairs', space.surface, camera.color) ships as ONE new migration file that re-creates background_library_validate_entity as a strict superset; never edit the two applied files (their bodies are pinned by tests/backgroundDatabaseContract.test.ts and were md5-verified against production on 2026-10-08). Database first, then the app: app-first means every save with a new field fails with 22023. (2) New map fields are optional; omitted means today's behaviour; a key is written only when the user picks a non-default and is deleted (never null/undefined) when reset; SQL validates and never fills or rewrites, because lost-reply recovery compares the submitted map verbatim (mapWorkflow.ts:7-14). No backfill of existing rows. (3) Re-run chain: the base file restores the narrow validator and admin-only execute/snapshot, so after ANY run of the base file re-run 3D -> B3 file -> B4 file, state that in each header and pin it with a test. (4) The first saved map that carries a new shape makes any PC still on v1.130.0 fail to load the entire background library (and an old client that saves at that moment commits on the server but shows a failure). This is acceptable only while the screen is owner-only: the owner updates every PC before using stairs, roads or camera colours. B3 also adds an 'update needed' reader (a typed unknown-shape error from the validator -> update prompt, saving blocked), and the screen must not be opened to other accounts (B4) by any version that lacks that reader; v1.130.0 itself cannot open the screen for non-owners because its gate is in the renderer. Never solve compatibility by dropping unknown fields on read: a whole-entity save would then delete them. (5) Everything else is additive and invisible to old clients: extra top-level snapshot keys are tolerated (domain.ts:94-99; electron/backgroundStore.ts:11-18) and side tables (editors, notes) with their wrappers are never called by old apps; apply their SQL before the app version that calls them. New anon-callable functions must NOT be named background_library_*: both the base file (DEVLOG/migrations/2026-09-21-background-library.sql:288-302) and the 3D file (DEVLOG/migrations/2026-10-07-background-map-3d.sql:107-119) revoke EXECUTE from every function with that prefix and re-grant only read/execute. (6) The preview browser store (key bflow-background-library-preview-v1) follows the same rule and must enforce the same permission and annotation rules as the server. All paths are under C:/Bflow-BGonly/.claude/worktrees/background-library-2d-3d-editor-a0ed8c.

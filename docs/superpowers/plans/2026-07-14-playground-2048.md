# Playground 2048 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 승인된 2048 목업을 기존 Arcade 지갑·기록·랭킹 계약에 연결된 production 게임으로 구현하고 v1.90.0으로 검증·배포한다.

**Architecture:** React와 무관한 결정론적 2048 엔진이 이동 trace를 만들고, `Merge2048Stage`가 trace를 150ms motion layer로 표시한 뒤 논리 보드를 commit한다. 기존 `ArcadeStageChrome`, Zustand store, Electron `ArcadeService`, Supabase RPC를 재사용하며 새 forward migration으로 닫힌 game allow-list만 확장한다.

**Tech Stack:** React 18, TypeScript, Zustand, CSS animations, Node test runner, Electron IPC, Supabase PostgreSQL.

## Global Constraints

- 작업 위치는 `C:\Users\user\.codex\worktrees\2048g\Bflow-BGonly`, 브랜치는 `codex/2048-게임-추가`다.
- `C:\Bflow-BGonly`의 목업 브랜치는 읽기 전용 기준 자료이며 수정하거나 릴리스하지 않는다.
- 테스트를 먼저 실패시키고, 최소 구현으로 통과시킨 뒤 정리한다.
- 기존 스네이크·테트리스 동작과 Arcade request/replay 계약을 깨지 않는다.
- 기존 적용 migration은 수정하지 않는다.
- 라이브 Supabase migration은 사용자의 별도 운영 승인 뒤에만 적용한다.
- DB migration은 앱 manifest 배포보다 먼저 적용한다.
- 모든 편집은 `apply_patch`로 수행한다.

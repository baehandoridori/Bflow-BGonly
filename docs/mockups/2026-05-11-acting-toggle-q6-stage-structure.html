Q6 / 8 · '단계' 의 구조

"1단계 / 2단계 / 3단계 / 4단계" — 어떤 모양으로 들어가나요?

한솔님이 "1단계/2단계/3단계/4단계로 나누어서 대체"라고 하셨는데, 그게 실제 화면에서 어떤 모양인지 두 갈래로 갈려요.
아래 두 시안 모두 같은 씬(SC_001)을 다르게 표현한 모습입니다.

시안 A

"단계마다 독립" — 각 단계가 자기만의 상태/차수를 가짐

한 씬 안에 4단계가 각각 따로 진행됨. 1단계에서 작업중→피드백→완료, 끝나면 2단계 시작, 동일 반복. 한 씬에서 "1단계는 끝났고, 2단계 작업중 2차, 3단계는 아직 대기, 4단계도 대기" 같은 상황이 가능.
장점: 실제 액팅 워크플로우(1원화→2원화→동화→최종)와 거의 1:1 일치 / 단점: 한 씬이 차지하는 세로 공간이 크고 정보 밀도 높음.

→ 한 씬에 4 × (대기/작업중/피드백/완료) = 총 16개의 상태 슬롯이 존재. DB 컬럼도 단계별로 따로 (예: stage1_state, stage1_work_round, stage1_feedback_round, …).

시안 B

"단계는 진행 마커" — 토글은 한 묶음, 단계는 어디까지 끝났나 표시

한 씬은 4개의 단계(1·2·3·4)를 순서대로 진행하지만, 토글(대기/작업중/피드백/완료 + 차수)은 현재 작업 중인 단계 하나에만 적용. 1단계가 완료되면 자동(또는 클릭)으로 2단계로 진입. "이 씬은 지금 2단계 작업중 2차" 같은 식.
장점: UI 단순, 한 행에 콤팩트하게 / 단점: 1단계 완료 후 2단계 진입 같은 단계 전환을 자동/수동 어떻게 할지 정해야 함.

미리보기 — SC_001 한 씬
001 SC_001 담당 · 김아무
1 2 3 4
단계 진행 |
대기 작업중 2차 피드백 대기 완료
해석: "1단계는 끝, 지금 2단계 작업중 2차 진행 중". 2단계 완료를 누르면 마커 2번이 ✓ 되고 3단계가 활성화.

→ 한 씬에 (현재 단계 1개) + (그 단계의 상태/차수 1세트) 만 존재. DB 컬럼은 current_stage, state, work_round, feedback_round 정도로 단순.

핵심 차이

관점 시안 A · 단계별 독립 시안 B · 진행 마커
한 씬 세로 공간 4행 (단계마다 한 줄) 1행
병렬 작업 가능? 가능 — 2단계 작업하면서 3단계 미리 시작 가능 불가능 — 한 시점에 한 단계만
차수 표기 단계마다 별도 차수 (1단계 1차, 2단계 5차…) 현재 단계 한 곳에만
기존 1원화/2원화/동화/최종 매핑 1원화 체크 = 1단계 완료, 2원화 체크 = 2단계 완료… 그대로 흡수 체크 개수로 현재 단계만 추정, 차수는 1로

제안: 실제 액팅 작업 흐름(1원화→2원화→동화→최종)에서 각 단계마다 검수가 따로 들어간다면 시안 A가 더 정확하고, 한 단계 끝나야 다음 단계 시작이라면 시안 B 도 충분합니다.

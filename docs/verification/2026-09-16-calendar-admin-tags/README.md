# 캘린더 안정화·관리자 열람·다중 태그·간트 가져오기 검증

- 작업 기준: `origin/main` `3b2ba3b7`, 독립 작업 폴더 `.worktrees/calendar-admin-tags`.
- 릴리스 버전: `1.120.0`.
- 사용자의 추가 요청으로 캘린더 → 간트 가져오기와 운영 배포를 진행한다. 아래는 구현 검증 기록이며, 최종 배포 증거는 `C:\Bflow-BGonly\output\release-audits\2026-09-16-v1.120.0`에 별도로 기록한다.

## 해결한 생성 오류

1. 캘린더 저장 확인 조회가 Realtime 재조회에 추월되면 `calendarsFresh:false`를 반환해 성공한 저장에 오류를 표시했다. `loadAll({waitForLatest:true})`가 같은 세션의 최종 조회를 기다린다. 최신 조회 실패와 계정 변경은 성공으로 숨기지 않는다.
2. 간트 폴더·프로젝트 생성 커밋 뒤 응답이 유실되면 생성 창이 남아 동일 ID를 다시 생성하면서 revision 충돌이 났다. 새 항목 생성에 한해 정본을 다시 읽어 동일 ID·내용을 확인하면 성공으로 복구한다. 자동 쓰기 재전송은 없다.

## 권한·호환성

- 운영의 배한솔 고정 ID와 관리자 역할을 동시에 검사한다. 다른 관리자에게는 열람 특례를 주지 않는다.
- 미공유 캘린더는 기본 표시 on, 목록은 기본 접힘. 개인별 제목 구분을 위해 소유자 이름도 표시한다.
- 열람 특례는 일정 편집 및 간트 프로젝트 열람을 부여하지 않는다. 기존 일반 캘린더에 대한 관리자 관리 권한은 유지한다.
- `tag_ids`가 정본, `tag_id`는 첫 태그 호환값. 기존 클라이언트가 같은 첫 태그로 저장하면 부가 태그를 보존하고, 다른 태그 선택은 교체하며 `null`은 전체 해제한다.
- 태그 추가·삭제는 서버 세션을 확인하는 관리자 RPC를 사용한다. 태그 삭제 실패 시 일정 초안 선택까지 보존한다.
- 마이그레이션: `DEVLOG/migrations/2026-09-16-calendar-admin-overview-tags.sql`. **새 앱 배포와 함께 운영 적용 필요.** 적용 이후 구버전 태그 관리 기능은 업데이트가 필요하다.

## 자동 검증

- 타입 검사: `npm run typecheck`.
- 전체 개발 빌드: `npm run build:vite`, 전체 2,643개 테스트(실패 0, 생략 0) 및 Vite/Electron main/preload 번들 생성 확인.
- SQL: `tests/calendarAdminTagsDatabase.test.ts`를 PGlite에서 실행. 기존 스키마·실제 RPC를 로드하고 신규 migration을 두 번 적용했다. 배한솔/다른 관리자/일반 사용자 권한, 구버전 조회·생성·수정, 여러 태그 보존·삭제·롤백, 비공개 간트 연결 일정의 읽기 전용 노출을 검사했다.
- SQL 실행용 임시 의존성은 레포 package 의존성에 추가하지 않았다. 재실행은 `BFLOW_PGLITE_MODULE`에 PGlite 모듈 절대경로를 지정하고 `node --test tests/calendarAdminTagsDatabase.test.ts`를 실행한다.
- 추가 태그만 바뀐 변경 감지, 여러 태그 중 하나라도 켜진 경우 표시, 삭제 태그 처리, 생성 응답 복구와 계정 전환을 회귀 테스트에 포함했다.

## 브라우저 검증

로컬 렌더러 프리뷰 `http://127.0.0.1:5186/?preview=1`에서 실제 UI를 조작했다. 프리뷰 로그인 후에만 확인했으며 운영 계정 데이터에 쓰지 않았다.

1. 배한솔: 새 일정에 업로드·회의를 함께 선택해 저장. 월 화면에서 두 색상 배지와 호버 툴팁 확인.
2. 생성 화면 안의 추가·삭제 → 새 태그 생성·색상 선택·저장 → 삭제 확인창 → 삭제 완료.
3. 장삐쭈 프리뷰 계정: 비공개 캘린더 생성 및 개인 일정에 두 태그 저장. 일반 사용자에게 일정 폼의 태그 관리 버튼이 없는 것을 확인.
4. 배한솔로 다시 로그인: 미공유 캘린더 2개가 접힌 관리자 전용 목록에 표시되고 다른 사용자의 개인 일정도 표시됨.
5. 해당 개인 캘린더 체크 해제: 일정 숨김·표시 개수 6/6→5/6. 다시 체크: 일정 복구. 목록을 접어도 표시 선택은 유지.
6. 브라우저 확인 중 캘린더 오류 로그 없음. 두 개 실제 PC에서의 운영 Realtime 전달은 이 프리뷰 확인과 별개이며 수행하지 않음.
7. 간트 화면에서 새 폴더·프로젝트를 생성해 목록 반영과 생성 창 닫힘을 확인. 네트워크 응답 유실 상황은 별도 회귀 테스트로 검증.

## 리뷰 반영

- 기존 클라이언트의 태그 사용을 막던 잠금 권한 문제를 재현하고 trigger 실행 권한을 조정했다.
- 관리자에게도 누락되던 미공유 캘린더의 간트 연결 일정을 보완했다. 연결되지 않은 비공개 작업은 포함하지 않는다.
- 태그 삭제 직후 빠른 편집이 삭제된 ID를 재전송하는 경로와, 삭제 실패 후 생성·상세 초안 선택이 복구되지 않던 경로를 수정했다.
- 프리뷰 관리자 권한 변경 후 이전 역할로 조회하던 문제를 수정했다.

## 캘린더 → 간트 가져오기

- B flow의 읽을 수 있는 개인·공유 캘린더에서 기간 및 일정을 선택해 편집 가능한 기존 프로젝트에 복사한다. 원본은 그대로 유지하며 이후 변경은 자동 동기화하지 않는다.
- 제목·메모·종일/시간·시작/종료일·색상을 보존하고, `importedCalendarEvent` 출처를 기존 작업 JSON에 보관한다. 간트 projection은 제외하고 역방향 `calendarId/calendarEventId`는 채우지 않는다.
- 동일 프로젝트의 중복은 JSON 저장·재조회 및 원본 캘린더 이동 뒤에도 제외한다. 실패 시 부분 저장이나 메모 잘라내기를 하지 않는다.
- 제출 직전 원본 일정과 대상 프로젝트의 최신 상태를 확인한다. 조회가 다른 요청에 밀려 적용되지 않았거나 공유 범위가 바뀌면 다시 확인하도록 한다.
- 실제 PostgreSQL 호환 엔진에서 세션 RPC 저장·재조회 후 출처 보존, 재가져오기 제외 및 캘린더 역방향 projection 없음 확인.
- 최종 `npm run build:vite` 전체 2,661개 테스트 통과(실패 0, 생략 0). 조회 경합과 폐기된 화면 효과의 재시도를 막는 추가 회귀 테스트를 포함하며 최종 타입 검사도 통과했다.
- 배한솔로 로그인한 프리뷰에서 보기 전용 ‘스튜디오 공지’의 ‘전체 회식’을 ‘검증 프로젝트’에 가져왔다. 차트 반영, 원본 보존, 다시 열었을 때 ‘이미 가져온 1개 제외’, 실행 취소로 제거 및 다시 실행으로 복구를 확인했다.
- 화면 증거: `gantt-import-select.png`, `gantt-import-result.png`, `gantt-import-deduplicate.png`.

## Supabase에서 확인하는 표

- `public.calendars`: 캘린더 이름과 소유자 `owner_id`.
- `public.calendar_events`: 일정 제목, 작성자 `created_by`, 소속 캘린더 `calendar_id`, 태그 `tag_ids`.
- `public.users`: 위 사용자 ID에 대응하는 `id`·`name`.
- `public.calendar_members`: 누가 어떤 캘린더를 공유받았는지 확인.
- `public.calendar_tags`: 태그 이름·색상.
- `public.gantt_spaces` / `public.gantt_projects`: 간트 폴더·프로젝트. 작업은 프로젝트의 `tasks` 안에 저장되고, 간트에서 보낸 캘린더 일정은 `calendar_events`에 중복 행으로 저장하지 않는다.
